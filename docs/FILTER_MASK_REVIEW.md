Production source reviewed and ten independent maintained checks passed, 2026-09-19. Root approved the final [FILTER_MASK_DESIGN.md](FILTER_MASK_DESIGN.md) after the enabled flag, native density expression, capture-work admission and full-source pre-read gate were pinned. Adobe documents one mask for the complete Smart Filter stack, with black hiding effects, white revealing effects and gray partially revealing them. Its guide also describes mask density, feather and inversion. This supports the interaction model, not a numerical, coordinate or file-format equivalence claim. ## Coordinate and pixel contract

Use the raster layer's retained source frame. Evaluate the ordinary complete stack on the original working RGB after separate source-cutout alpha has been combined. Let that original effective RGBA be O and the complete filtered RGBA be F. Apply the mask once to interpolate only RGB between O and F, then run existing geometry, protected-context RGB restoration, additional masks, opacity, groups and clipping unchanged.

The mask must not alter effective source alpha, mask out Gaussian neighbors, scope individual filter entries, or follow document selection implicitly. Source spatial filters still observe all visible source neighbors. Source alpha, every alpha byte and zero-effective-alpha RGB remain exact. Alpha1 is eligible RGB, just as in the existing stack. Active entries remain structurally active even under an all-black mask; disabled mask and density0 mean fully reveal the stack, not disable it. Neither a visually unchanged result nor zero effective scope relaxes source-edit/protection/Bake restrictions or filter work admission.

The mask stays in its source frame across document crop, resize, canvas bounds and layer geometry. Do not call the additional-mask geometry transforms on it. Source filtering already precedes geometry, so applying a canvas-space mask after interpolation would be a different operation. An inverse-resized canvas selection is not an exact substitute: mask mixing and image resampling generally do not commute.

Minimum useful authoring supports explicit source-coordinate rectangle, ellipse and bitmap descriptors and explicit selection capture, plus enabled/feather/invert/density settings and removal. Polygon selections may be captured into a bitmap; direct polygon filter masks are outside the proposed first slice. No per-entry masks, positioned wrappers, filter-mask painting, automatic capture on filter creation, mask-to-selection loading or recipe serialization of scope is required. Direct source descriptors must be validated against the retained source width/height; bitmap dimensions must match exactly. Reject misplaced position/density metadata and unsupported extra wrapper fields.

## Exact coverage and RGB interpolation

Pin the new policy's quantization order rather than claiming parity with continuous additional-layer-mask coverage:

1. Evaluate source mask shape, raw feather and inversion using the existing raw mask semantics.
2. Quantize raw coverage once to byte M.
3. Compute an effective byte E from density d with the declared native operation order: `clamp(Math.round(255 - d*(255 - M)))`.
4. For each positive-effective-alpha pixel and channel, compute `halfUp((O*(255-E) + F*E)/255)`.

Root chose the current native bitmap-density expression, without reducing stored Number precision or reinterpreting it as decimal or exact unrounded IEEE rational arithmetic. Build a256-byte lookup table using the specified multiplication, subtraction and rounding order; pixel loops only perform a byte lookup. Density0 explicitly yields255 for every raw value; density1 yields the raw byte. Disabled masks can bypass callback/table creation while still validating their complete descriptor. Density0 may likewise bypass raw callback construction; raw preview must still evaluate it.

The intermediate floating rounding is intentional and is not an exact-real density claim. At density0.1 a raw black pixel becomes230, matching the native byte expression; exact unrounded arithmetic on the represented binary value would yield229. The latter alternative was considered and explicitly rejected. The independent probe checks all256 raw bytes at44 representative dyadic, non-dyadic, adjacent-to-half, subnormal, endpoint and seeded values, using separately implemented BigInt dyadics to emulate each floating operation's ties-to-even rounding. Raw geometric coverage is quantized before this density stage, so it still differs from continuous geometric additional-layer-mask coverage.

For the final mix, integer numerator T=`O*(255-E)+F*E` is between0 and65025. `floor((2*T+255)/510)` is exact in Number arithmetic and gives exact O/F endpoints. There is no extra floating blend stage, alpha multiplication, premultiplication, or candidate rounding before this final stack boundary. Existing per-entry rounding/blending stays unchanged.

A concrete discriminator is two full invert filters: their complete output equals O, so any whole-stack mask must also equal O. Masking each invert separately at byte128 instead drives the tested inputs toward127/128. This detects accidentally implementing a per-entry mask.

## Explicit selection capture

Allow capture only when the actual geometry stream is a partial one-to-one integer source map: crops, canvas translations, and the exact byte-copy affine predicate (`scaleX/Y===1`, rotation0, no flips, integer x/y). Reject every resize/resample and other affine, even if its net bounds or apparent transform are identity. Document why a transformed source must be captured before those operations or authored directly in source coordinates; do not silently resample a mask.

Compile both a source-to-canvas offset and a surviving source rectangle. Intersect survival at every intermediate operation. Net offset alone is insufficient: crop source columns1–2 from width4, then pad one column on each side, has net offset0 but a full final selection must capture `[0,255,255,0]`, not all-white. Cropped pixels do not return when later bounds expand.

Sample the current selection at mapped integer pixel centers for surviving source pixels and write0 elsewhere. Capture selection coverage alone, ignoring source alpha, additional masks, opacity, visibility, clipping, ancestors and protection. Quantize once to alpha8 and encode bounded RLE. Null selection rejects; an explicit empty selection remains an all-zero source mask. Capture is a snapshot, not a live link; reset captured feather/invert/density settings so they are not applied twice. The source is an image frame, not the selected layer's visible bounds.

The existing600,000-scalar RLE and16MiB project/history limits apply before commit. Account source alpha materialization S plus retained selection callback C (up to5 canvas pixels for bitmap feather), without image/source I/O. New sample/RLE loops yield. The owner proposes an async bitmap preparation path with byte-for-byte legacy feather arithmetic and unchanged5S allocation, yielding through decode/distance/output loops. Use that path both for source masks and bitmap selection capture rather than inheriting a potentially long synchronous large-mask preparation step. Decode scheduling must count actual visited cells/runs; checking only absolute source indices divisible by65,536 lets sparse runs avoid yielding. Existing legacy call paths need not change.

Memory bounds alone do not bound polygon capture CPU. Let V be the exact surviving source rectangle area, H its sampled row count, P the polygon's edge count, and S the whole source count scanned for output/RLE. A conservative proposed transient charge is `S + 8V + 2PV + H*P*(2+ceil(log2(P))) + bitmapPreparation`, with absent terms zero for other shapes and bitmap preparation N/8N for unfeathered/feathered selection coverage. Bound this separately at384million units before allocation or coverage construction; do not add this one-shot authoring operation to persisted filter work. The2PV term covers crossing and edge-distance visits; per-row setup accounts for crossing/filter construction and sorting even when the surviving rectangle is only one pixel wide. Polygon sampling must also reduce per-yield pixel batches by its weight so256-edge coverage cannot execute millions of edge checks between nominal65,536-pixel yields. This charge is an admission estimate, not a proof of a wall-clock deadline or the engine's internal sorting implementation.

## Compatibility and accessor inventory

Persist a strict versioned alternate `layer.filters` object only when a mask exists, containing nonempty entries and its mask definition. The latest root scope includes a separate enabled boolean, preserving density while disabled; it must be present in strict normalization, Modify, capabilities, preview and resource predicates. Keep old unmasked arrays exactly as arrays, including omission. Current old readers reject a non-array filters value; they silently accept an unknown top-level `filterMask`, so that field alone is insufficient for fail-closed files. The independent probe verifies both behaviors against the current validator.

Public documents retain `filters: []` as the established entry array and expose separate mask metadata through an explicit projection in `asDocument`; persistence, undo snapshots and `.prism` graphs keep the wrapper. Public projected metadata must never be fed back into persisted graph storage and silently lose scope. The native graph validator rejects misplaced top-level mask metadata. Older clients can still edit entries through new native commands because the backend preserves the mask wrapper; their source-edit guards continue seeing a nonempty public array.

Audit every direct array assumption, especially these pre-I/O guards:

- `native.mjs`: fill/extract/cutout-alpha refinement; placement; paint/retouch; source renderer; active-filter protection; staged entry edits and Bake plan/clear; source previews with `filters:false`.
- `layer-filters.mjs`: normalization, counts, work, activity, spatial/shared resources and rendering. Masked inactive stacks still have entries and block source editing.
- `filter-bake.mjs`: unwrap entries and mask together; evaluate the masked complete stack, then restore original working alpha as before. Inactive-only Bake clears entries and mask with zero image I/O. Active Bake keeps the earlier-protected-content rejection, including hidden/nested content, regardless of mask appearance.
- `asDocument`, history, duplicate/subtree clone and `.prism` import/export: preserve wrapper identity and validate it before asset reads. Clear, final entry deletion and Bake consume the mask. Removing only the mask returns a legacy array. Reordering/updating/appending preserves scope.
- Client public-array consumers: `RasterTools`, `CanvasTools`, `CutoutPanel`, `canPaintCutoutMask`, `LayerFilters` counts/new-ID selection, protection/activity helpers and recipe capture. They remain safe only if every public response uses the same projection.
- `psd-export.mjs` already rejects non-array or nonempty filter stacks; retain that rejection for masked and disabled stacks. PSD import must not fabricate wrappers. Flattened exports render scope normally; editable `.prism` retains it.

Recipes must refuse capturing masked stacks rather than quietly transferring only entries. Existing recipes may append to a masked target only if the contract explicitly retains that target's existing scope; no recipe step should silently remove or replace it. Recipe validation remains metadata-only and must include resulting work/memory admission. Saved styles continue excluding all filter state.

## Protection and bounded lifetimes

The original effective input is already retained by `renderLayer`; no new before-stack image copy is needed. The completed filtered buffer is owned. Construct mask coverage after `applyLayerFilters` returns and mutate that buffer's RGB in a separate helper. Return only the mixed buffer so callback/LUT references do not survive into later geometry. This keeps spatial ring and mask callback in separate phases rather than summing them unnecessarily.

For S source pixels, G the largest geometry frame, C the raw mask callback storage and L at most256 LUT bytes, the renderer's additional phase peak is conservatively `max(8G, 8S+ring, 4S+C+L)+canvasPixels`, before existing group/clipping reserves, positioned-mask callback reserves and the shared Gaussian-noise table. A feathered source bitmap contributes C=5S, so the mask phase can exceed a tiny-ring filter phase. Direct rectangle/ellipse masks need no full typed plane. Captured polygon selections become bitmaps; any temporary polygon row caches during capture remain separately bounded JS metadata. Skip C/L only for a genuinely bypassed mask path, while still validating metadata.

The owner's direct masked evaluator also proposes a complete-source phase ceiling `max(12S+ring,8S+C+L)+T <=256MiB`. If retained, this same predicate must run in graph metadata validation for every evaluated masked leaf, using graph-wide shared table T. The additional-buffer graph gate alone can admit a24MP scalar mask whose direct12S phase exceeds256MiB, leading to a late refusal after source decode. The owner accepted adding this missing pre-read predicate. Mask disabled/density0 and wholly inactive entries should preserve the corresponding bypass admission, while their complete metadata still validates. Wholly inactive `applyLayerFilters` returns the caller input, so skip mask mixing rather than assuming that buffer is owned.

Bake must compare its existing filter phase `E+(hasAlpha?17:12)*S+ring+64KiB` with the new mask phase `E+(hasAlpha?13:8)*S+C+L`, plus the shared table. Original/effective/alpha/filtered references coexist during this latter phase. Decode, encoding and publication phases remain unchanged; the table is still counted in all phases. The callback must not remain live into encoding. These are named-buffer limits, not RSS/codec/GC guarantees.

Mask preview should sample source dimensions, not document canvas dimensions, and must state that coordinate frame. Reuse the bounded opaque grayscale preview output, nearest-center dimensions and transfer ledger, adding C/L to its sampling phase. It must not decode RGB, render the document or write assets. Existing selection/additional-mask sources retain their current canvas dimensions and behavior.

Metadata changes that activate masks, feather, density, entries or spatial filters must validate the candidate graph before assigning it. A transaction step that changes source-mask resources must reject before a later operation can render, segment or store an asset. Existing transaction preflight keyed only on positioned additional masks is insufficient by itself. Real persistence and late Bake transaction failures must preserve graph/history and use the existing owned-asset cleanup scope.

The current proposal adds8S to persistent document filter work whenever entries are active and the mask is enabled with density>0. It does not inspect white/black samples to discount the cost. Disabled masks, density0 and inactive stacks add zero mask work, with existing entry work/count/protection unchanged. The added term joins the existing384million budget and must be checked on mask, entry, recipe and hidden-layer activation. This is separate from the transient capture-work admission above.

Protected-source footprint construction remains based on source alpha plus the existing additional masks/opacity, never the filter mask. Mask interpolation occurs before contextual protected RGB restoration; it cannot attenuate or bypass the restoration. Generated hard exclusion and clipping consumption remain later rules. Source-oriented transparency selection, subject sampling, Current repair sampling and any explicit `filters:false` preview must ignore the entire filter stack and its mask together.

## Independent evidence and acceptance gates

`test-results/filter-mask-review/probe.mjs` and `report.json` are design-only artifacts. They pass689,824 integer RGB-mix comparisons against BigInt,11,264 density entries against an independently implemented IEEE-operation oracle,14,199 capture samples across500 random crop/canvas/integer-affine programs, and100 direct comparisons with the actual native geometry renderer. They also pin the repeated-invert distinction, alpha/hidden RGB preservation, the lost-then-padded domain fixture and old-reader compatibility behavior. A current native blur produces62 in a neighbor that an incorrect input-alpha mask would reduce to0. A two-source-pixel resize fixture yields source-mixed0 where resized original/filtered values are25/175, so no document-space interpolation could reproduce that source result. These distinguish both stage-order hazards using existing production geometry/filters. No production mask helper exists in these tests.

The maintained [filter-mask-audit.test.mjs](../tests/filter-mask-audit.test.mjs) passes ten independent checks against the production helper and native backend:

- All256 raw bytes at14 representative densities/inversion settings match an independently emulated IEEE multiplication/subtraction stage and exact BigInt final mixing. Alpha0/1/128/255, inactive input aliasing, whole-stack double inversion and unmasked Gaussian-neighbor sampling are pinned.
- Async bitmap feather matches legacy callbacks across64 small cases. A131,072-run sparse mask that avoids absolute loop boundaries still yields. Eighty random capture programs independently reconstruct surviving source pixels, including lost-then-padded coverage; polygon and bitmap-feather CPU admission rejects before sampling.
- Public arrays and separate read-only scope metadata coexist with internal wrappers. Disabled entries under a disabled density0 mask still block fill, extraction, cutout paint/refinement, brush/clone/heal and placement. Entry append/reorder retain scope; clear-mask unwraps and final deletion consumes it. Source-alpha selection remains independent.
- Raw/effective inspection of a64×3 source cropped to a5×3 canvas samples the retained source frame. Missing working/source/alpha assets do not matter. RGB/model/filesystem spies remain untouched, and inspection leaves project/assets/cache unchanged.
- Full-source24MP activation fails before pixels, including subnormal positive density. A near-boundary combined graph includes nested isolated groups, clipping, the Gaussian-noise table from another leaf and retained positioned-mask sources; feather activation and a transaction preceding later rasterization reject without I/O. - Independently computed source alpha, a two-filter stack with fractional opacity/Multiply, inverted source coverage and density0.1 survive fractional affine geometry, positioned additional-mask density, an isolated group, a clipping member and upper protected content. Bake preserves every source RGB byte, restores original working alpha, consumes scope and exactly preserves the composite.
- Original-context RGB restoration, generated clipping exclusion and previews remain protected. Black/disabled masks do not relax earlier hidden protected-content Bake refusal or structural protection of active entries; protected inactive targets still reject mask edits.
- Recipe validation and application include cumulative mask work with no pixel/file I/O. A valid append preserves scope. Malformed disabled wrappers, source frames, coverage and public-projection fields fail portable import before asset access.
- Real ENOTDIR publication failures and a late modify-mask→Bake→paint→missing-layer transaction preserve graph/history/cache and remove newly owned working assets.
