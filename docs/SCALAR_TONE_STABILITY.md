# Legacy scalar tonal repeatability

Resolved during Local Shadows / Highlights browser acceptance, 2026-09-19.

The browser harness compared an unchanged 96×72 document containing legacy global Shadows(+35) followed by Highlights(−25). Its first export sometimes omitted the Shadows treatment from a suffix of the image. The later export matched the independent formula on every byte; graph, revision, input assets and alpha were unchanged. This affected visible RGB as well as hidden RGB. For example source `[45,190,10,1]` became `[35,180,0,1]` in the affected baseline suffix (Highlights alone), whereas the correct full sequence is `[41,186,6,1]`.

An independent reproduction retained the fixture setup and Chromium launch but performed no navigation or client edits. Its first export differed from the next eight. Instrumenting `applyAdjustment` located the discrepancy in the first Shadows result before encoding; the protection plane contained only zeros. Disabling optimization or concurrent recompilation avoided that reproduction. Suppressing optimization of `applyAdjustment` alone did not. Optimization traces showed compilation of the anonymous scalar color closure/map callback near the discrepancy. These observations narrow the execution-sensitive path; they do not establish a particular upstream compiler defect or claim that a general V8 bug has been proven.

`server/color.mjs` now selects legacy Shadows/Highlights once when creating their transform. The returned function computes the same luminance, power, signed offset and final byte clamps explicitly for R, G and B. It avoids creating a nested scalar-switch map callback for each pixel. Arithmetic order, constants, ranges, source/global alpha policy and masks/protection remain unchanged. The new neighborhood-based `shadows_highlights` source filter remains separate.

After the refactor, five fresh normally optimized processes each produced nine identical global exports. The focused native/color/tonal/blend/local suite passes 65 tests. The independent maintained `tests/scalar-tone-regression.test.mjs` adds three cases: two fresh Node processes compare every byte over alternating half-megapixel shadows/highlights calls, source and global paths retain their distinct hidden-alpha and protection/mask/opacity semantics, and the unchanged 96×72 global stack remains exact through unrelated local edits. The ordinary browser suite also passes all eight workflows, including its original before/after global comparisons; no test disables optimization or waives the pixel assertion.

Diagnostic artifacts remain under `test-results/`: `local-tone-global-browser-repro.mjs`, `local-tone-global-instrument.mjs` and its optimization log, `color-before-tonal-dispatch.mjs`, `local-tone-global-stability-report.json`, and `local-tone-global-adjacent.log`. Maintained regression code lives outside that ignored diagnostic directory.
