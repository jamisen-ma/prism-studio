# Seeded source noise: research notes

Research only, 2026-09-19. No implementation is authorized by this note. Finish Unsharp Mask acceptance before beginning a new source-filter implementation.

Adobe's current [filter effects reference](https://helpx.adobe.com/photoshop/using/filter-effects-reference.html) describes Add Noise with Uniform, Gaussian and Monochromatic options. Its [UXP layer reference](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/layer) exposes an Amount range of0.1–400%. Those are useful workflow references, not a definition of Adobe's random sequence or byte arithmetic. A native source Add Noise filter would fill part of the missing general-filter family and work with existing editable stacks, recipes, baking and protected composition.

Potential bounded scope: source-only `add_noise`, required `value:0`, complete parameters `{amount:5,distribution:'uniform',monochromatic:true,seed:1}`. Amount could support0–400% in canonical0.01% increments, where0 is an explicit identity; distribution is Uniform/Gaussian; monochromatic means a shared RGB delta; seed is an unsigned32-bit integer including0. The exact range, distribution and defaults still need review. Global adjustments remain unchanged. A separate source capability marker would pin the deterministic algorithm and its parameter meaning.

Reproducibility is essential: preview, export, Bake, history, recipes and reopening must generate the same pixels. Never use `Math.random` or fresh per-render entropy. A new-pattern action should change only a local seed draft, with an explicit normal save. Store the seed rather than relying on filter IDs, target IDs, project IDs or processing order. Sampling should use original source pixel coordinates and channel; skipping zero-alpha pixels must not advance or shift a stateful sequence for later pixels. Retained geometry should transform the already sampled source result.

Candidate design for investigation: a specified uint32 counter hash with `Math.imul`, followed by a16-bit symmetric midpoint uniform deviate. Source index/channel mapping must be collision-free within the24MP ceiling and stable across opacity/visibility/mask changes. Add encoded-RGB deltas, clamp and round the candidate once, then use existing filter opacity. Shared RGB deltas can still alter hue after channel clipping, so Monochromatic must not promise exact hue preservation. Every alpha byte and zero-alpha RGB stays exact; additional masks and selections retain later semantics.

For Gaussian, compare a compact pinned integer inverse-CDF table with direct floating Box–Muller. A bundled table can define identical bytes across runtimes and avoid transcendental variation during rendering, but its discrete quantiles, truncation, scale, provenance, hash and shared-memory reservation need explicit documentation and tests. Generating that table must use an independent high-precision oracle or sufficient error margins around integer quantization, not merely trusting one floating calculation. Do not call a12-uniform sum an exact Gaussian; either document a deliberate approximation or choose a defined discrete normal distribution.

With midpoint uniform numerator `2*u+1-65536`, amount centipercent A and channel C, the candidate numerator can be `C*(65536*10000) + (2*u+1-65536)*255*A`, denominator `65536*10000`. These products fit exact Number integers at A<=40000; an independent proof must cover half-up division and clamping. A quantized Gaussian table could use an analogous fixed denominator. This may avoid arbitrary floating byte boundaries without a per-pixel BigInt path, but it is only an arithmetic candidate.

Required feasibility evidence: fixed known vectors and independently computed byte oracles; histogram/mean/variance and neighboring/channel correlation checks over enough samples; several seeds including0/maxuint32; positive/negative delta symmetry; no bias from alpha skipping; Amount versus opacity; narrow/wide yields and measured1MP/worst admitted workloads; no extra full image planes beyond the existing candidate; native normalization/recipes/portable refusal before asset reads; preserved originals/protected/generated contexts and exact Bake. Choose a conservative source work weight after measurements. Amount0 remains structurally active while enabled at positive opacity, with identity work1 and no random/candidate computation.
