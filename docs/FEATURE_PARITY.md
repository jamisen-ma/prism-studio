# Standalone native feature parity

Research and implementation snapshot: **2026-09-19 UTC**.

The product goal is a standalone image editor whose real editing tools can be operated through the UI or MCP from natural-language instructions. **Photoshop installation is not required.** The existing Photoshop bridge is optional legacy integration and is not a dependency or release gate for native development.

This document extends the [71-tool toolbar inventory](PHOTOSHOP_TOOL_INVENTORY.md). A toolbar list is a discovery aid, not the complete Photoshop feature set, and neither tool counts nor this matrix are a parity percentage. Layer semantics, filters, typography, color management, file fidelity, automation and performance need their own acceptance tests.

## Baseline and evidence

Adobe's current desktop [release page](https://helpx.adobe.com/photoshop/desktop/whats-new/whats-new-in-adobe-photoshop-on-desktop.html), reviewed for this snapshot, lists August 2026/version 27.10 and separately labels AI Assisted Editor as Beta. The baseline below is the documented desktop workflow. Beta capabilities must retain that label; announced, wait-list, archived and other-product features are not automatically treated as released desktop requirements. Adobe's [Neural Filters overview](https://helpx.adobe.com/photoshop/desktop/effects-filters/neural-filters/overview-of-neural-filters.html) itself distinguishes released, Beta and wait-list filters.

**Adobe links establish the comparison target. They do not prove our implementation.** Native status comes from [validated commands](../shared/commands.mjs), [native implementation and declared limits](../server/native.mjs), [generation contracts](../shared/generation.mjs), the associated tests, and [verification status](IMPLEMENTATION_STATUS.md). Concurrent work is not counted until it lands and passes relevant checks.

- **Implemented, scoped:** the stated native operation works; the wording does not imply all Adobe options or identical pixels.
- **Partial:** useful native behavior exists, but significant workflow, fidelity or control gaps remain.
- **Missing:** there is no native end-to-end implementation of that family.
- **External service:** implemented orchestration may still depend on a provider and available quota. Local image editing remains independent of that provider.

The current native renderer is 8-bit sRGB and processes full images in memory. Limits are 8,192 pixels per axis, 24 megapixels, 64 total layer/group nodes, eight nested groups, 100 retained history states and 16 MiB project metadata. Raster-image transfer through UI/MCP accepts at most30 MiB decoded bytes; the internal native decoder has a separate32 MiB ceiling. PSD and `.prism` binary imports have their own documented limits. These are current limits, not professional-scale performance targets.

## Dependency-based implementation order

These are engineering stages, not dates or claims of already completed work. Tool/UI work can proceed in parallel when it uses a stable underlying contract.

| Stage | Work that unlocks the next stage | Exit criteria |
| --- | --- | --- |
| 0 — Capability and evidence baseline | Keep the native capability manifest, UI, MCP schemas and this matrix consistent; create versioned fixture and benchmark manifests. | Unsupported options fail clearly; implemented operations work through both UI and official MCP; fresh installation completes a local edit/export with no Photoshop present. Existing selection/protection/source-preservation regressions remain green. |
| 1 — Layer graph and compositing | D2/D3, mask coordinate contracts and graph migrations; design typed pixel/color metadata for later precision work. | Three-level group fixtures cover pass-through/isolation, nested opacity, clipping, hidden layers and masks. Reparenting preserves order; cycles reject atomically; old projects migrate; undo/reopen reproduce exact 8-bit fixtures. |
| 2 — Editable objects, effects and precision design | D4/D5/P8, plus C1/C2/C3 UI tools using the same graph. | Replacing an embedded source updates two differently transformed instances; effect/filter parameters remain editable after reopen; rendering matches declared alpha/order rules. Text and vector edits stay editable rather than silently rasterizing. |
| 3 — Advanced selections and photo tools | P1/P2/P3/P5/P6 and geometric extensions in D7. | Named/channel masks round-trip, selection algebra matches reference coverage math, sampled tools honor source/target coordinates, mesh edits cancel cleanly. Matting quality has a reviewed fixture set including omitted accessories; all source-RGB guarantees remain exact. |
| 4 — Color, RAW and interchange | C4 first; P9/C5/C6/C7 follow their required graph/color features. PSD raster/group subset may begin alongside Stage 2, but advanced round-trip waits for corresponding native types. | 16-bit ramps retain precision; float values survive supported operations; profile assignment and conversion differ correctly. ## Shared acceptance rules

1. **Pixel and data integrity:** keep immutable originals; use exact byte comparisons where semantics are deterministic. Operations restricted by selections/protection must preserve every excluded pixel. For resampling, color conversion or model outputs, state the tolerance or quality metric and why exact equality is inappropriate.
2. **Editable state:** serialize parameters and references, not just a flattened preview. Verify undo/redo, reopen, project migration, source/working distinction and missing-resource behavior.
3. **UI/MCP consistency:** the same operation and defaults must agree through both interfaces. Mutations accept stale-state guards; read-only inspection must not change revision, history or assets. Preview coordinates, intrinsic dimensions and visible bounds remain explicit.
4. **Atomic failure and bounded work:** malformed inputs, cancellation, exhausted storage and invalid graph operations must leave the document intact. Test child-process shutdown and resource limits with isolated fakes; do not use provider calls for routine regression tests.
5. **Provider and model truth:** separate local inference, mocked provider success, built-in session generation and API generation. Keep stable request IDs, no automatic generation retries, retained output and hard local masking. Real segmentation preserves source RGB but can omit accessories. Built-in generation and actual MCP artifact completion are verified for one inspected background; synthetic selected edits prove local mask/protection enforcement. The separate API path returned a quota error and is no longer the requested default.
6. **Compatibility reporting:** each format lists supported features and any loss before export. Unsupported layered content must not be silently advertised as an editable round-trip. Reference Adobe specifications and public behavior; binary/plugin and proprietary model compatibility require separate evidence.
7. **Performance claims:** measure the current renderer before selecting numerical targets for the next engine. Proposed fixture tiers are a 24 MP editing document, a deeply nested layer document and a larger-than-memory stress case once tiling exists. Record hardware, peak memory, first-preview latency, edit latency and cancellation latency; these are proposed tests, not measured capabilities.
