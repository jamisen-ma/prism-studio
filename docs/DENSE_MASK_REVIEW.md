## Coverage semantics must be independent of storage

Dense alpha8 is another representation of the existing bitmap byte field. In [`layerMaskCoverage`](../server/layer-mask.mjs#L161), the current bitmap branch explicitly recovers `Math.round(coverage * 255)` before applying the native density expression. The new type must take the same byte-valued branch. Treating it as a continuous geometric mask can change density rounding, especially after inversion. Source effect masks have their own raw-byte quantization and density LUT, which must remain unchanged.

Preserve the existing sequence: raw alpha8, inward feather to bytes, inversion, positioned source/domain clipping, then additional-layer density. Source effect-mask density and whole-stack RGB mixing retain their existing separate stages. Raw inspection ignores layer density but still reflects the declared feather/invert semantics. Cropping feathered bytes must bake the old feather before clipping; canvas expansion must not invert newly exposed padding into coverage. Resize must retain the currently declared sampling rule. Empty selection remains an explicit mask and must never become `null`/select-all.

The canonical dense descriptor should carry a new strict shape and verified immutable asset identity, byte length and dimensions, with editable feather/invert kept as metadata. Do not add an optional `asset` to the old bitmap shape. Reject malformed own fields before getters or coercive schema copies. No image path, MIME guess or mutable byte array belongs in the descriptor.

## Raw versus encoded storage

Raw alpha8 is the simpler first complete contract: exact expected length, one channel, no color management or codec interpretation, predictable preparation and exact content hashing. Its cost is disk/history/bundle volume. This is a preference for design evaluation, not permission to raise current limits.

A compact typed header containing the format/version and dimensions is worth comparing with bare raw bytes. With bare bytes, the same payload can have several width/height interpretations; the typed walker must either reject incompatible descriptors for one hash or deliberately define those aliases. A header makes this distinction part of the immutable content. In either choice, reject cross-kind aliases with raster, source-document and LUT assets before reads; never overwrite a prior type in the traversal map.

Lossless encoded alpha is a larger contract. It must pin bit depth, channel meaning, dimensions, single-image status, metadata behavior and decoded length, with bounded reads and decoding before use. Existing `readAlpha`/`storeAlpha` are cutout-alpha conveniences, not a sufficient new storage verifier: `readAlpha` accepts PNG then extracts channel zero. An arbitrary PNG with RGB, profiles, extra frames or ambiguous alpha must not acquire new coverage semantics by filename. Encoded input, decoded bytes, an owned feather copy, distance scratch and output/encoder buffers can overlap. Compression ratio is not a working-memory bound.

## Simultaneous lifetime requirements

The present [`estimateLayerMaskCallbacks`](../server/layer-mask.mjs#L77) estimate is `2 * sum(bitmap source pixels) + max(4 * feathered source pixels)`. Its proof depends on two retained callback sets and only one synchronous [`maskCoverage`](../server/masks.mjs#L61) feather constructor. Making preparation asynchronous invalidates the latter claim if constructors are started concurrently. Prepare sequentially, or admit the sum of concurrently live read/decode/distance buffers. A `Promise.all` over masks cannot retain the old maximum-only estimate.

Concrete overlaps in the current renderer are:

- Group coverage remains captured by recursive `renderNodes` while children render. Isolated or pass-through groups can also retain RGBA and protection surfaces.
- A clipping base mask survives all member awaits. A member callback, base interior, member image and protected footprint coexist.
- `protectedPixels` builds ancestor coverage before awaiting each protected source. Contextual inspection can perform this pass while callbacks from the visible render remain live.
- A global adjustment retains input, output and its own mask callback. Color Lookup also retains its compiled table; parser preparation and already-live ancestor masks require the joint phase bound.
- A source effect mask is prepared after filter evaluation, with original and completed source RGB retained. Additional/ancestor callbacks may already exist. Bake, capture, morphology and selection combinations each have different output and publication phases.
- PSD export retains prepared mask planes across later rendering and layer collection; its preparation peak is not just the writer's peak.

Dense-containing graphs need an explicit resource opt-in even without Distort or Color Lookup. Extend the existing joint content/ancestor/clipping/protection/noise/table phases rather than adding an independently passing 256 MiB check. Include retained positioned source size, which may exceed the current canvas. Direct preview, source inspection, Bake and mask-edit calls must agree with graph admission before pixel reads. State existing codec/global spatial/style exclusions honestly.

Avoid a graph-wide decoded cache initially. Scoped deduplication is safe only if its retained sum is counted and bytes are immutable: feather preparation currently mutates its alpha plane, so two references with different feather values cannot share that mutable working plane. Callback identity also includes inversion, density, position/domain and raw/effective mode. Repeated decodes consume work even when a hash is shared; cumulative preparation work needs its own bound. Render/request closures must be released before the next operation, with no buffers attached to graph/history/API records or module-global caches.

## Asset, history and publication completeness

`projectAssetUses` currently walks raster fields, LUT entries and the source archive. Add active selection, all saved selections, every additional mask including positioned sources, and source filter-stack masks, independent of visibility/enabled/density. Apply typed consistency across all retained history states. Dense verification must not be conditional on `hasColorLookup`.

Prospective commit must enforce history count/byte limits before publication, including transactions that create several assets and branch after Undo. Startup verifies all retained references, including history-only masks; portable export verifies and includes current references only. Define storage limits separately from per-pass preparation work and working buffers. The bundle also has a **193-asset count limit**, in addition to its 256 MiB byte limit and 16 MiB manifest limit. More small mask assets can reach that count without approaching either byte limit. Preserve existing limits unless a separately reviewed policy changes them; refusal must be explicit.

Every asset-producing mask operation needs the established owned-file rollback scope, including formerly metadata-only selection/canvas commands. Test existing-hash reuse, shared saved masks, late transaction failure and real persistence failure. Never clean an asset belonging to prior history or another document. No collection policy should be inferred from current-graph reachability alone.

Recipe definitions currently do not transport mask assets. Keep that boundary explicit: do not capture a dense dependency through an incidental metadata field. Ordinary dependency-free recipes may still operate in a document containing dense masks if their bound targets and render phases support them. Preserve the existing source effect-mask capture refusal; avoid a blanket document-wide recipe ban.

## Smallest complete acceptance scope

Start with one explicitly named full-resolution continuous channel producer and one dense format, without importing arbitrary mask image files or adding a mask library. Pin channel/alpha meaning separately. Demonstrate exact bytes on the original 512² photograph and a 1 MP high-frequency fixture, then cover:

1. Active and saved selection sharing, mixed RLE/dense Add/Subtract/Intersect/Replace, feather/invert, explicit empty coverage and raw/effective grayscale inspection without RGB reads.
2. Selection-to-additional/adjustment mask, painting and clear/fill under coverage, cutout refinement, and edit-input mask export. Source effect capture must either support the input with its existing geometry constraints or reject before allocation/mutation with truthful capabilities.
3. Crop, resize and resize-canvas across active/saved/additional masks atomically, including feathered boundaries, inverted padding and positioned sources larger than the canvas. Unsupported edits must be explicitly disabled/refused, not accepted and later lost.
4. Ordinary, protected, generated, isolated-group and clipping rendering; source inspection; existing LUT/Distort/Noise/filter-mask overlap; PSD support or a precise preflight refusal.
5. Undo/Redo, restart, portable round-trip, typed alias failures, malformed inactive/history-only descriptors and bytes, storage/work boundaries before reads, and late transaction/ENOTDIR rollback.
6. Client preview/selection drawing and capability withdrawal with source dimensions, revision and request ownership. No full-resolution alpha payload in ordinary document responses.

The overlay must not assume that a hash in the saved graph grants access to raw asset bytes. Extend the bounded [`mask-preview`](../server/mask-preview.mjs#L43) transport with owned requests for this purpose; the full-precision server mask remains authoritative for edits. A reduced preview is display-only, never a replacement selection. Reject unsupported shapes explicitly instead of drawing the current rectangle fallback. Raw/effective mode, source frame, document/revision, selection identity and capability changes must invalidate late preview responses.

This is infrastructure work across consumers, not a new shape switch in `normalizeMask`. The initial review identified storage, verification, lifetime, history and complete-consumer decisions. The follow-on isolated probes below resolve the byte policy and proposed metadata limits; they do not demonstrate production integration or measured performance.

## Follow-on channel and quota proposal

This section extends the read-only review after Photo Filter implementation was released. [`DENSE_MASK_ARCHITECTURE.md`](DENSE_MASK_ARCHITECTURE.md) adopts the framed raw direction and serial preparation; the full implementation design remains pending. No native code or maintained test registration is changed here.

Recommend five explicit composite-selection coverage channels: Red, Green, Blue, encoded Rec.709 luma and Alpha. Read the freshly rendered current composite RGBA8, including its visible stack, without using the active selection as an extra measurement boundary. Stored adjustment masks naturally remain part of rendering. Derive one coverage byte per pixel:

```
RGB:   coverage = halfUp(channelByte * alphaByte / 255)
Luma:  Y8 = floor((2126*R + 7152*G + 722*B + 5000) / 10000)
       coverage = halfUp(Y8 * alphaByte / 255)
Alpha: coverage = alphaByte
Invert, if requested: coverage = 255 - coverage
```

Luma is deliberately rounded to a byte before alpha multiplication. `[14,1,122]` has exact encoded luma12.5: its luma byte is13, and alpha128 yields coverage7. Multiplying the unrounded12.5 by alpha first would yield6 and is a different policy. RGB/luma alpha multiplication has denominator255, so its exact rational values have no mathematical half ties; all integer operands are small and an integer half-up expression is straightforward. Luma can have exact halves and must use the declared integer expression. This is encoded luma, not perceptual lightness or linear luminance.

With no inversion, every RGB/luma coverage lies between0 and alpha; hidden RGB at alpha0 cannot select pixels. Final inversion intentionally selects transparent pixels (coverage255) and can exceed the original alpha. Do not label it “invert color before transparency.” Alpha is used directly, never squared. Explicit all-zero output remains an empty selection; `null` still means there is no selection.

Channel inspection should display an **opaque grayscale preview of this exact proposed coverage**, including inversion, with clearly named channel and semantics. It is not an unassociated-channel visualization with another alpha blend. Use the existing exact preview dimensions and nearest-pixel-center convention; the reduced display never supplies edit pixels. Applying selection recomputes at full resolution under captured revision ownership. Combination occurs afterward using the existing Replace/Add/Subtract/Intersect algebra; it must not multiply the active selection into source measurement or reclassify channels.

The independently authored `test-results/dense-mask-evaluation/review-channel-reference.mjs` defines a BigInt reference and twenty literal RGBA cases across alpha0/1/128/255, primaries, neutral ramps, a mixed color and the double-round discriminator. It imports no prototype or production code. The same literals can later validate both opaque previews and full-resolution selection storage; probe execution and production comparison are separate evidence.

The proposed **3 GiB / 256 unique framed alpha assets across retained history** is reasonable for the stated100-state editing goal, subject to a separate preparation-work and storage policy. With a provisional32-byte header,100 distinct24MP masks total2,400,003,200 bytes;134 maximum-size masks total3,216,004,288 bytes and fit3,221,225,472, while135 exceed it. The count cap remains useful for many smaller masks. All arithmetic must use safe integer Numbers, not signed32-bit coercions:3 GiB already exceeds the signed32-bit maximum.

Count compatible hashes once after prospective redo truncation and the existing100-state trim, while checking every typed use for compatibility before deduplication. Source/working RGB, LUT originals and source archives retain their own budgets; mask bytes must not be silently charged to or exempted from those policies. Enforce the same mask metadata/count/byte limits at commit and startup before payload reads. Reads on startup should be serial and bounded; a3 GiB history cannot be verified by loading all blobs together. A verification-work policy must not accidentally make a newly admitted history impossible to reopen.

This quota is neither a disk limit nor a guarantee that every admitted current graph is portable. The current store lacks global garbage collection, and abandoned redo/pruned successful blobs can remain on disk. Portable transfer still has193 unique assets and256 MiB for the entire bundle, plus its manifest limit. A long history with only one current mask can export comfortably; a current graph with many dense masks may correctly exceed portable limits even though its retained history is allowed. Expose that existing refusal honestly, without increasing or conflating the limits.

Before the new channel command can produce its first dense descriptor, its **input** graph may contain no dense masks, LUT or Distort at all. Therefore the command needs a forced joint render preflight; activating stronger admission only when a dense shape already exists would miss that first extraction. The materializer phase retains rendered4N plus extractedN, then returns only the coverage plane before combination/publication. Serialization/hash/write staging must count an additional framed buffer if it copies the coverage. Exact formulas must distinguish these sequential maxima from group/protected/clipping callbacks that remain live across awaits.

## Joint phase corrections and remaining design conditions

The proposed dense-only graph envelope is reasonable as a **named reachable-buffer** bound:

`6Q + maximum retained group/clipping surfaces + simultaneous mask callbacks + shared noise + max(all content leaf phases, global adjustment phase, decoration phase) + existing global Curves-bank reserve`.

Force this preflight for both proposed channel commands even on an otherwise legacy graph. The separate [`get_channel_preview` plan](DENSE_MASK_MCP_DESIGN.md) correctly renders RGB intentionally, then samples opaque grayscale directly into a bounded preview. It must not inherit the selected-mask endpoint's no-RGB-read promise. The render phase and subsequent composite4Q plus sampled/codec/encoded/base64-transfer phase are sequential maxima, with exact document/revision/channel/invert ownership. No full-resolution channel plane is needed for preview. Ordinary mask inspection still reads only the selected mask asset.

Including known existing spatial/style buffers in this new opt-in ledger is justified: dense masks and first-time channel extraction can render those branches. Source review found these concrete phase requirements:

- [`spatialAdjustment`](../server/adjustment-filters.mjs) returns a candidate4Q before `applyAdjustment` allocates output4Q. Its alpha-weighted median also uses3264 histogram bytes; a conservative8Q+3264 phase covers that branch. Scalar adjustment output is4Q, and Levels plus legacy/smooth Curves retain an additional256-byte lookup. The same source-filter median/LUT storage must join the new leaf cache maximum, plus the8-byte IEEE blend setup for tiny sources; reusing the old Distort helper literally omits those constants. The final owner design makes this dense-only extension without changing legacy admission. Global bank/lookup preparation retains its existing separately named phase rules.
- [`renderOutsideEffects`](../server/layer-effects.mjs) retains source4Q, alphaQ, occupiedQ and output4Q. When changing blur sigma, the previous blurred plane remains live while new padding and a new blurred plane are constructed. `10Q + 3*maxPaddedPixels` is conservative; same-sigma reuse and an unblurred alias do not require extra planes.
- [`outsideOutline`](../server/cutout-pixels.mjs) adds output4Q, horizontal Uint16 data2Q, occupiedQ and row scratch**20H+8**. Including source4Q gives11Q+20H+8, or15Q+20H+8 when a completed outside-effects RGBA plane remains live. The row term matters for narrow/tall images. A4096×3000 example with a dense additional mask and effects+outline requires282,684,072 named bytes under these phases; an envelope omitting decoration reports only147,456,064 and wrongly admits it.
- Additional-mask callback storage includes full framed backings, not just payloads. Two24MP callbacks, one feathered, require a conservative192,000,128 bytes for two retained callback sets plus one Float32 distance plane. Constructors must stay serial. Source filter-mask preparation remains a distinct deferred phase inside the leaf estimate, after candidate/ring preparation closes.

Publication also has a real deduplication phase. [`storeAsset`](../server/native.mjs) retains incoming framed bytes while [`readBoundedHandle`](../server/bounded-file.mjs) reads an existing same-hash file to verify it. The reader allocates exactlyB bytes and hashes64KiB views; there is no extra EOF-probe byte. With only the final candidate alpha plane retained, publication is `Q + 2B = 3Q+64`, or72,000,064 bytes at24MP. A new-file path uses `Q+B`. These are not valid bounds if an old source plane or callback still survives: storing inside the present combination helper can retain inputQ, outputQ and two framed buffers, reaching4Q+64 plus the active-mask callback. Use an explicit helper scope that returns only the completed plane before publication, or charge all retained inputs. The same rule applies to paint, morphology and canvas transforms.

The graph envelope alone does not cover every edit call. In [`fill_area`](../server/native.mjs), selection coverage exists before flood rendering, and selection/flood callbacks survive source and protection rendering. `paint_stroke` retains targetRGBA while sampling a composite, then target/sample surfaces while preparing selection and protected pixels. Their command preflights must add these external retained inputs, or deliberately shorten the lifetime. Source-mask capture, morphology, preview and PSD retain their own existing command phases; serial processing may return descriptors between masks but cannot erase a still-reachable source plane from the estimate. Codec internals, arbitrary JavaScript metadata overhead and process RSS remain outside the named-buffer claim.

Finally, **two simultaneous callback sets is not a preparation-work limit**. A metadata work plan must count each potential preparation invocation, including repeated references. With proposed byte-mask weightsN unfeathered/8N feathered, ordinary rendering charges each visited additional mask and evaluating source filter mask. A `protectedPixels(context,before)` call adds, for every preceding protected content layer, its own additional/source mask and every ancestor additional mask. Contextual inspection can repeat this entire prefix for each contextual content or clipping base. Hash equality does not eliminate those preparations. Direct layer inspection, PSD exact-mask preparation, active selection combination and edit-specific protection calls add their own occurrences. Use an operation-specific schedule or a clearly conservative repeated-prefix upper bound before reads; do not describe this as a bound on all preexisting rendering CPU. History verification is a separate serial operation and must remain possible for every newly admitted3GiB history.

The independent metadata schedule fixture demonstrates the distinction: one feathered1MP ancestor with ten contextual protected content children costs368 million preparation visits and fits; eleven costs448 million and refuses. The ordinary composite of the same eleven children needs only8 million. The final operation-specific policy permits ordinary rendering while refusing the more expensive isolated preview before reads. This fixture allocates no pixel planes.

The final owner design incorporates the complete consumer matrix, per-operation plans, retained-source corrections and final-plane-only publication scopes. These resolve the independent backend design blockers. For a newly computed mask, its unique hash is not known until the candidate frame has been produced; finish prospective unique-history admission before storing/publishing that frame. Existing known references and intermediate transaction graphs remain subject to their earlier preread checks. This distinction prevents an impossible promise to determine a new result's deduplication before computing it.

The shared metadata module and declarations were also reviewed: strict own-data copying, exact frame length/hash/origin, null/default distinctions, canonical negative-zero feather, frozen storage/preparation limits and independent channel preview limits agree with the contract. Its original four focused checks passed in the root's run. Maintained native validation of the explicit lifetimes, invocation plans, rollback scopes and all consumers remains a separate gate; passing isolated helpers is not a substitute.
