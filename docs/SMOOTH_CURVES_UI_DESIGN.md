## Contract and compatibility

Extend the existing Curves controls for both global adjustment layers and source filters; no new kind or command. Global kinds stay 24 and source kinds stay 28. Parameters retain `points`, `channel` and `value: 0`, adding optional `interpolation: 'linear' | 'smooth'`. Omission means Linear. Existing omitted Linear records must stay unchanged. Effective channel defaults to RGB, effective points to the current diagonal endpoints; a valid explicit Linear record opens clean without a mount write.

Smooth uses `curvesInterpolationPolicy: 'shape-preserving-pchip-v1'` and `curvesInterpolationModes: ['linear', 'smooth']`. The gate requires the matching native backend, the exact policy, a well-formed string array containing `smooth`, and existing context-specific kind/command support. Unknown strings may coexist with recognized values; a mixed nonstring array authorizes no Smooth. Linear retains its existing legacy support even when the new fields are absent, malformed, empty or unknown. A global Curves capability does not imply source-filter support, or vice versa. Root confirmed the native-backend requirement; the optional Photoshop bridge will reject explicit interpolation.

The renderer keeps legacy Linear arithmetic unchanged. Smooth uses the native shape-preserving cubic rule and a 256-byte lookup. Authored integer knots are pinned to their rounded output value; exact `x === y` points produce the identity table. A two-point smooth curve is mathematically straight, but native floating evaluation can differ from legacy Linear at a half boundary. No Photoshop parity, exact-real rounding or restored clipped detail is claimed.

## Shared precise draft controls

Extract or replace `CurvesControl` with one shared implementation used by `ColorWorkbench` and `LayerFilters`. A small pure helper owns effective defaults, canonical comparison, parsing and pointer coordinate decisions; the parents own the complete draft. A proposed `CurvesDraft` contains channel, interpolation and an array of `{x: string, y: string}`. Strings are never converted merely by mounting, selecting another point, drawing the graph, changing mode or editing another coordinate.

Numeric fields use `step="any"` and strict finite decimal/scientific parsing. Blank, incomplete exponent, Infinity, NaN, hexadecimal, values outside 0–255, duplicate X and crossed X remain visible invalid drafts and disable Apply. A valid configuration has 2–16 points, first X exactly 0, last X exactly 255, and strictly increasing intervening X; no minimum gap, tolerance, quantization or forced Y ordering. Endpoint input fields are read-only. Every coordinate not explicitly edited retains its exact Number on parse and command submission. In particular, changing Y at X `0.1` between `0` and `0.2` never changes X, and valid adjacent/subnormal coordinates survive.

Provide an explicit point selector, identifying points by stable draft index and input/output values. This makes near-coincident points independently reachable without pixel-accurate clicking. Keep the selected point when a field becomes invalid; switching the selector preserves all invalid strings. Delete applies only to an interior selected point and never changes the remaining coordinates. Graph insertion remains a convenient integer-coordinate authoring action; insert only if the resulting X is unique, strictly internal and below the 16-point limit. Do not carry over the old two-unit insertion exclusion. Numeric editing can subsequently locate the new point at any valid fraction.

The same parser drives both parents' validity; remove the global editor's current `points.length >= 2` shortcut. Compare complete effective canonical settings, treating omitted/explicit Linear and equivalent numeric strings as equal. An untouched saved curve has Apply disabled. Reset is a local draft action restoring the existing Curves defaults (RGB, diagonal endpoints, Linear); it neither saves nor removes the attached mask/filter blend/opacity. Unsupported saved Smooth settings remain read-only, including Reset, until support returns; do not offer an accidental conversion path on a companion unable to execute their current mode.

On Add, Linear omits the new parameter. On an ordinary unchanged-mode update, canonical Linear may also omit it. **Switching a saved Smooth record to Linear must explicitly send `interpolation: 'linear'`**: update operations merge parameters, so omission would retain Smooth. Smooth always sends its marker. The rest of the complete valid draft is submitted without precision loss. Backend normalization removes explicit Linear from the resulting stored record. Recipe capture uses canonical omission, not this transient reset argument.

## Graph and interaction ownership

Keep the existing grid, diagonal and optional composite histogram. Linear retains its straight authored-point polyline. Smooth imports `compileSmoothCurveLookup(points)` from `shared/smooth-curves.mjs`, drawing its actual 256 byte samples at integer inputs; do not approximate with SVG spline commands or a second PCHIP implementation. Mark authored points separately, including fractional points between input bytes. The graph is a draft transfer-function preview, not a live document edit or a promise that masks/blends/source alpha are shown in that chart. If the draft is invalid, show its validation message and suppress the current curve line instead of silently displaying a last-valid line as if current.

Use an explicit pointer ticket containing owner epoch, pointer ID, captured element/bounds, point index, exact pre-gesture string draft, starting pointer and exact starting coordinate. Only the captured pointer may move or finish it. Use movement relative to the captured grab position: an off-center click without movement changes nothing. A vertical drag leaves fractional X unchanged, and a horizontal drag leaves untouched Y unchanged. Moved axes use the existing bounded integer graph authoring convention. If an integer X candidate is not strictly between its neighbors, retain the original exact X; do not clamp to `neighbor ± 1`. This also allows useful vertical dragging in an interval narrower than one input unit. Numeric fields remain the precise way to move such an X.

Pointerup evaluates only the owning ticket and captured geometry; a view/layout change cancels instead of mapping through a new rectangle. Escape, pointercancel, unexpected lost capture, control unmount, target/revision change, capability change or busy transition cancels and restores the exact pre-gesture draft only if that ticket still owns the same draft session. Old cleanup cannot restore over a replacement target/draft. Normal release clears ownership before releasing pointer capture. Selecting a point/channel/mode or editing a numeric field first cancels the owned drag, then applies the deliberate new local action to the restored draft. Apply is disabled during a drag.

Pass `busy` and read-only/context identity explicitly into the SVG control: a disabled ancestor fieldset does not reliably disable SVG pointer handlers. Graph events stop propagation and cannot start a canvas drawing gesture. Disable graph mutation when any coordinate draft is invalid, while keeping point selection and numeric correction available. Maintain a monotonically advancing epoch so away-and-back identity or capability changes cannot revive an old pointer or pending command.

## Recipes and scope

Capture/import are definition operations and may retain Smooth without execution support. Capture saved settings only, ignoring local unsaved strings. Canonical Linear omission preserves legacy recipe definitions/hashes; Smooth is explicit. The existing refusal to capture filters from a masked stack remains, with deliberate Filters opt-out permitting style-only capture.

Validate/Apply checks inspect both source `add_layer_filter` parameters and global `update_adjustment` steps whose declared slot kind is Curves. Require Smooth support for a Smooth step and for an existing Smooth adjustment target that would be changed, even if the requested final recipe settings are Linear. Source checks include disabled entries, existing mode/blend/source/effect-mask gates, and the existing target mask. Bindings and both new capability fields invalidate a ready report and delayed validation result. A filter-only recipe appended to a supported masked target keeps the target's mask.

The backend design provides the crucial Linear recipe reset: at execution staging only, an omitted-mode canonical global Curves recipe sends explicit Linear to clear a Smooth target. The UI must not change recipe bodies/hashes to implement that reset or change application retry/reconciliation. Application deduplication remains same-session; after restart, stale revision and explicit reconciliation rules remain unchanged.
