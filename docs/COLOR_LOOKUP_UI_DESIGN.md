# Color Lookup import and controls: UI design

Status: implemented, 2026-09-19. Eight focused and 83 adjacent browser workflows pass, and the final TypeScript/Vite build passes. This implementation follows [the workflow evaluation](CHANNEL_WORKFLOW_EVALUATION.md), [the independent reassessment](NEXT_PRO_WORKFLOW_REASSESSMENT.md) and [the numerical/asset review](COLOR_LOOKUP_REVIEW.md). Root and independent review accepted the command, descriptor, parser, numerical, asset and phase contracts; the native seam is implemented. Architecture supplied the capabilities, limits and new-global selection behavior below.

## Useful first slice

Import one local `.cube` file directly into a new global Color Lookup adjustment or a raster source-filter entry, and replace the file on an existing Color Lookup without changing that layer/entry's other saved settings. Each successful import or replacement is one native operation and one Undo. The sole durable LUT asset is the original immutable file; a separate upload stage, library, favorite list or public local-hash picker is unnecessary.

The first slice must include original-file preservation, reopening, Undo/Redo and `.prism` transfer, not merely a transient preview. Existing layer removal, filter deletion, Clear and independently supported Bake provide useful removal paths. Selecting the same local file again may deduplicate its immutable bytes internally; the UI does not expose this as an asset-library feature. Do not show an unimplemented reuse/export-library action.

The implemented `import_color_lookup` target union is below. Every request includes `documentId`, positive `expectedRevision`, canonical-base64 original `data`, safe-basename `sourceName` and explicitly chosen `inputSpace: 'srgb'`.

| Target | Add | Replace |
| --- | --- | --- |
| `target: 'adjustment'` | Omit `layerId` | `layerId` identifies an existing Color Lookup adjustment |
| `target: 'layer-filter'` | Required `layerId`; omit `filterId` | Required `layerId` plus existing Color Lookup `filterId` |

Result: `{ document, layerId, filterId? }`. Saved parameters: `{ asset, bytes, gridSize, inputSpace: 'srgb', sourceName, title? }`, where title is parsed native metadata. `sourceName` is a nonempty well-formed safe basename up to 200 UTF-16 code units, with no control characters or slash/backslash; reject rather than silently rename a disallowed file. Optional parsed title is retained exactly under native title validation and is separate from the filename. Ordinary `add_adjustment`/`add_layer_filter` must not manufacture a Color Lookup with missing assets, and raster `import_image` must not receive text disguised as an image. The import command replaces only the file descriptor, preserving unrelated saved settings.

## File draft and input interpretation

Use a shared compact file card within the global adjustment path and source-filter inspector:

1. **Choose .cube file** opens a local chooser. Capture the initiating target before opening the chooser. Selection, reading and changing the choice are local only; do not upload or create an asset yet. Clear the hidden input value after each chooser result so the same file can be selected again. Cancelling the operating-system chooser leaves the previous valid local choice unchanged.
2. Show the chosen basename and exact original byte size. The browser extension/MIME is a chooser hint; native parsing decides whether the contents are supported. Reject a zero-length or over-limit file before reading, using the final advertised limit. Display filenames as text; never interpret a title or filename as markup, a filesystem path, or a statement about color space.
3. **Input/output interpretation** initially reads **Choose interpretation**. The supported choice is **Encoded sRGB (0–1)**. Choosing it is a local declaration, not a conversion or inferred profile. A newly selected replacement file resets this choice; a cancelled chooser preserves the previous file/choice. The old saved lookup's interpretation does not automatically acknowledge a different file. No default checked acknowledgement and no extra confirmation dialog are needed.
4. The final **Import Color Lookup** or **Replace lookup file** action is enabled only with a file, explicit interpretation, a current eligible target and supported capabilities. Adjacent copy states: **“Interpret this file as encoded sRGB. It will be validated when applied.”** Read/boundedly encode the captured file only as needed for this operation; validate ownership again after every await and before dispatch.

Before native parsing, do not invent a grid size/title from a partial header or say the file is compatible. Initial UI can show **“Grid and title are checked during import.”** A shared, bounded, read-only inspection helper may be used later if architecture provides one, but a duplicate browser parser or another upload endpoint is not required for this slice.

An unsupported-file refusal retains the local file and explicit interpretation for inspection/replacement, without creating a layer or asset. A valid different replacement file is not applied merely by choosing it. **Discard file draft** restores the saved inspector; before dispatch it has no native side effects. While import is dispatched, use **Applying…** and disable file/interpretation mutation; closing or navigating away cannot promise to cancel a native commit already in progress.

Always-visible explanation: **“A 3D color lookup changes RGB using the imported file. Transparency is preserved.”** Keep detailed scope in an accessible collapsed **About Color Lookup** disclosure:

- This version accepts the declared native subset: 3D `.cube` grids 2–33, RGB samples and identity input domain in 0–1. Larger valid `.cube` files, 1D/shaper combinations, different domains and extended-range output are unsupported; no silent resampling or clamping of the authored table.
- A normalized file can still have been designed for log, HDR or scene-linear input. Prism cannot infer that intent from a 0–1 table and performs no such input/output conversion. Choose a look intended for encoded sRGB or explicitly accept that interpretation.
- Native trilinear evaluation preserves parsed Float64 samples and uses the declared native operation/rounding order. Do not promise Photoshop/OpenColorIO parity, tetrahedral interpolation or universal exact-real half-tie rounding. Numerical detail belongs in the public guide, not the primary controls.

## Saved controls and replacement

Saved inspection shows **Color Lookup**, original filename, optional parsed title, grid (for example **33 × 33 × 33**), byte size and **Encoded sRGB · Native trilinear**. These are immutable saved metadata, not editable text fields. Reopening does not reread the user's original path or ask for the file again: the project contains its verified original bytes. Do not display a bare asset hash as a portable file reference.

| Context | Controls and scope |
| --- | --- |
| New global adjustment | A dedicated file card in the existing adjustment entry path. No meaningless Value slider or Apply that submits an empty descriptor. Import creates the adjustment and adopts the current selection as its mask, like `add_adjustment`; captured revision prevents silently using a later selection. State this scope beside the action. |
| Saved global adjustment | File metadata and a replacement draft. Existing layer opacity/blend and additional-mask controls remain separate. Replacement preserves layer ID, name, order, visibility, opacity, blend, mask and other unrelated saved properties. |
| New source filter | Dedicated file card for a selected raster layer. New entry starts at Normal, enabled and 100% opacity unless the native contract explicitly provides different defaults. After import, existing precise filter opacity/blend controls apply. No separate “Intensity” parameter. |
| Saved source filter | Metadata and replacement, plus existing entry enable, exact opacity, blend and order controls. Replacement preserves entry ID/index/enabled/opacity/blend and the stack's shared effect mask. Source image assets and cutout alpha remain unchanged. |

Source lookup is evaluated on source RGB in entry order, before geometry; entry blend and opacity keep their established meanings. The filter effect mask mixes the completed stack. The layer mask controls final visibility. A global adjustment evaluates the composite according to existing global-adjustment behavior. The UI must not describe source and global scopes as interchangeable.

File-only replacement must not silently discard a pending opacity/blend draft during its successful revision remount. Use the bounded rule **“Apply or reset filter settings before replacing the file.”** Keep those exact settings strings intact and disable starting/submitting replacement while they are dirty. While a local replacement file is being reviewed, keep saved generic source settings inspectable but disable their mutation; **Discard file draft** returns to ordinary settings editing. This avoids a separate settings Apply silently remounting away a chosen file. New LUT creation uses the specified defaults, so there is no unsaved source-settings conflict. Do not add optional generic settings to the import command solely to avoid this clear sequencing rule.

Pending local file drafts survive capability withdrawal on the same target; saved metadata remains readable. Replacement failure leaves the current lookup visibly saved. Do not automatically remove the saved entry, silently reset its mask/blend, or append a second lookup as an alleged replacement.

## Capability partitions and inspection

Architecture supplied `colorLookupPolicy: 'cube3d-f64-trilinear-srgb-v1'`, `colorLookupFormats: ['cube-3d']`, `colorLookupInputSpaces: ['srgb']` and `colorLookupLimits`. Current native limits are `maxBytes: 4194304`, `minGridSize: 2`, `maxGridSize: 33`, `maxPrepareBytes: 33554432`, `maxHistoryBytes: 67108864`, `maxHistoryAssets: 128`, `maxTransactionBytes: 4194304`, `maxLineLength: 4096`, `maxNumberLength: 64`, `maxTitleLength: 200`, `maxSourceNameLength: 200` and `maxWorkingBytes: 268435456`; source pixel work32S is internal to the native policy, not an advertised workPerPixel field. These preparation/history budgets are not extra file uploads or library controls.

Use one shared support predicate/signature for the new kind, with independent scope/action checks. The predicate requires Native, the exact lookup semantic/format policy, encoded-sRGB interpretation support, valid required format/size limits, the advertised kind in the relevant scope and `import_color_lookup` for import/replacement. Honor valid smaller advertised byte/grid limits; do not require equality with hardcoded 4 MiB/33. Require finite positive integer budgets and an ordered supported integer grid range. Source additionally requires source coordinates and all existing mask/blend/protection conditions for the target. Validate typed lists; a malformed mixed list fails the relevant gate, while future unknown strings can coexist with the recognized required subset. Include the full semantic and resource signature in pending-operation ownership; native remains authoritative for graph/history/preparation admission.

Never derive new import support solely from `add_adjustment` or `add_layer_filter`, and never require the generic creation command if the atomic import contract independently advertises that action. Check add and replace independently if capability fields distinguish them. A saved lookup inspector remains mounted when the import/replacement command or semantic marker disappears. Filename/title/grid/interpretation and explanatory help remain inspectable; no mutation fallback converts it to an ordinary scalar adjustment.

Include the lookup signature in entry and whole-stack execution identities. A saved unsupported lookup blocks editing/enabling it and reordering its stack because those actions execute/recontextualize it. Existing Delete/Clear and independently advertised Bake retain their own explicit removal/protection gates; no extra permission dialog. Ordinary supported filter kinds remain available where the saved graph can legitimately be evaluated. Do not impose a blanket ban on every edit in a document merely because it contains a LUT.

For a missing or corrupt retained asset, report the native failure; never display identity pixels as a successful lookup, substitute a different file, or silently fetch a remembered local path. Client resource refusals do not downsize the table, reduce image dimensions, change opacity or bake on the user's behalf.

## Draft, request and preview ownership

Keep a stable local session separate from capability identity. It owns target scope, document/backend/expected revision, layer/filter identity, chooser/read epoch, selected File, interpretation and any frozen submitted envelope. Source filter selection, global target selection, document/backend navigation, close/reopen and capability transitions monotonically invalidate old work; A → B → A must not revive an earlier request. Reading a file or choosing an interpretation never changes pixels.

- Capture the chooser owner **before** opening the native dialog. If its target changes while the chooser is open, ignore the late result; do not attach it to whichever layer is now selected. An old read failure/finally must not clear a newer choice or busy state.
- A same-target external revision change leaves the file draft visibly stale. Do not silently substitute the new revision. An explicit **Review current target** reload can retain the local file while binding a new reviewed revision. It is a local review action, not automatic replay. Target navigation does not transfer a draft to another layer/document.
- Freeze the exact submitted bytes, filename, interpretation, target, expected revision and one request ID before dispatch. Validate busy and ownership after file reading/encoding and immediately before dispatch. Later draft actions cannot mutate this envelope.
- On success, validate the returned document/backend, expected single revision increment and the returned/uniquely identified target entry. A replacement keeps its captured IDs; creation acknowledges only its own new ID. Perform the existing narrow precise-color handoff **before** publishing metadata, so the operation's own revision remount/first selection does not invalidate itself.
- Recheck ownership before installing metadata, after the preview await, before selecting a created entry and before closing/resetting this draft. Pass an acceptance callback into preview installation; an obsolete preview must not overwrite the current canvas. The operation may already have committed natively even when its obsolete UI result is suppressed.
- Guard `REVISION_CONFLICT` refresh and any subsequent preview with the same epoch/target checks; no old catch may reopen an earlier document, revive a closed import, discard a newer file or automatically reapply.

The existing generic `App.run` currently generates a fresh request ID through `command()`. Give each deliberate Apply one frozen stable ID and exactly one dispatch, with a narrow option/adapter only if needed to use that captured ID while retaining the existing guarded metadata/preview installation pattern. No new receipt infrastructure or recipe recovery refactor is required.

Architecture confirms existing same-session request deduplication and **no new durable receipt**. On a lost reply, report **“The reply was not received. Refresh this target before applying another lookup.”** Reconcile the fresh graph/revision and require the user to inspect it before another deliberate Apply. First-slice UI needs no retry button or automatic reupload; a new request ID is created only for a new deliberate action on a reviewed target. After restart, an old expected revision must stale-reject; do not advertise recovery across restart as proof of which operation committed. A refresh/reconciliation can reveal the saved state, but an ambiguous same-hash existing entry is not a substitute for a receipt.

## Recipes, portability and MCP

First-slice recipe definitions cannot carry a lookup asset dependency. Refuse lookup-bearing slots/steps, source entries and capture, including disabled/zero-opacity LUT entries; a local hash does not make a recipe portable. This is narrower than a document-wide restriction:

- A selected source stack containing a lookup cannot be captured with **Filters** checked. Explain the dependency and allow the user to explicitly uncheck Filters to capture available style-only settings. Never silently omit just the lookup entry or reorder the rest into an apparently complete recipe.
- A lookup adjustment cannot be captured as a portable adjustment recipe. If other independent capture categories genuinely apply, offer only an explicit selection of those categories; do not manufacture an empty adjustment definition.
- Definition import/save/export must reject dependencies, not just execution. Preserve ordinary dependency-free recipe capture and execution in a document already containing a lookup, including appending supported filters while retaining the existing stack/mask. Existing target semantic/resource gates still apply.
- Keep recipe retry/receipt behavior unchanged. Lookup-related capability changes enter the relevant validation/application context when a bound target stack depends on the lookup, without treating an unrelated lookup elsewhere in the document as a reason to invalidate everything.

Editable `.prism` carries the verified original LUT and descriptor alongside source imagery; flattened PNG/JPEG exports carry the result. This milestone does not add Photoshop-native LUT interchange claims or recipe asset packaging.

MCP should use the same strict atomic operation with explicit interpretation and positive expected revision. A user-selected local-file adapter may read that exact bounded `.cube` and provide original bytes. The agent must not first upload an unreferenced LUT and then separately mutate the graph. The browser never passes local paths as server read authority. Root owns this adapter/schema/tool-help work; this UI design does not create a second protocol.

## Compact layout and accessibility

Use the existing dark field/button styles and a single-column file card at the 900 px viewport. Keep current filename, interpretation, action and short scope copy visible together. Wrap a long filename/title without widening the inspector; use an accessible full-text label rather than tooltip-only information. File choice and interpretation are keyboard reachable, loading/error states have status/alert semantics, and details use a native accessible disclosure. No enormous preset gallery or modal confirmation is needed.

Saved metadata/help remain usable while busy or read-only. Mutations—file replacement, interpretation changes, Apply and generic settings—remain disabled during the captured submission. Closing an inspector or switching targets is navigation, not an assertion that a pending server commit was cancelled.

## Eight focused acceptance groups after approval

1. **Local choice and strict import.** Native global/source creation, initially unselected interpretation, chooser cancellation/reselection, zero/oversize rejection before reading and malformed/unsupported native parsing. No graph/history/asset change before Apply or after rejection. Saved filename/title/grid/bytes match verified original bytes. No generic blank-descriptor Add path.
2. **Declared pixels and scope.** Independent fixed files: identity grids and endpoints; red-fast asymmetric channel permutation; size-2 red gain 255/256 giving input128 →128 (protect against Q16 regression); an approved nontrivial Float64 fixture. Source/global alpha and invisible RGB behavior, source blend/opacity plus filter mask, geometry ordering and raw Bake equal the frozen native reference. No generic exact-real oracle near unpinned half ties.
3. **Replacement and history.** Replace global/source lookup atomically with stable IDs and unchanged masks/settings/order/source bytes. Dirty generic source settings prevent accidental loss. Cancelled/bad replacement preserves the old look. One Undo/Redo restores the full prior/new descriptor and appearance. Delete, final-entry deletion, Clear and Bake retain established shared-mask behavior.
4. **Capabilities and protection.** Independent add/replace/global/source partitions, wrong policy/interpretation/format/limits, malformed lists and Photoshop backend; withdrawn capability preserves file draft and saved inspection. Unsupported saved entries cannot enable/edit/reorder; permitted explicit removal remains accessible. Protected and transformed source behavior follows native policy, without covert rasterization.
5. **Chooser/read/dispatch ownership.** Hold chooser or file read; change document, source entry, scope, capability, revision or close/reopen, including away/back. Old result/failure/cleanup cannot change a new draft or send a command. Block overlapping busy submission, preserve stale draft and require explicit current-target review.
6. **Response, preview and reconciliation.** Hold command success and preview separately for add/replace; navigate or withdraw support. Reject old metadata/preview/selection/close actions while a valid own revision installs exactly once, including no-selected-layer creation. Hold revision-conflict refresh too. Duplicate clicks do not duplicate import; uncertain reply prompts owned refresh/inspection without automatic resend, and restart does not produce a false durable-receipt claim.
7. **Portable state and dependency boundary.** Original LUT bytes/hash retained across save/reopen/restart and `.prism` round-trip with exact exported pixels; missing/corrupt/descriptor-mismatched assets refuse. Masked/LUT stack recipe capture explicitly blocks Filters; opting out captures styles only. Dependency-bearing definitions reject; unrelated dependency-free recipes still work on documents containing LUTs. No recipe retry regression.
8. **Photographic and accessible workflow.** Use the existing original NASA fixture without new generation, an authored maintained useful look fixture with provenance, actual before/after exported PNGs and an independently defined expected transform. Review global/source at 900 and 1440 px; keyboard chooser/interpretation, long metadata, collapsed help, replacement and opacity/blend remain readable. No console errors, external provider calls or credentials.

Reviewer maintains independent fixtures at `tests/fixtures/color-lookup/reference.mjs`: `authoredCube`, `authoredLookupGolden`, literal goldens and malformed cases, with original file SHA/provenance. Identity, RGB-cycle, nonseparable cross-products and gain-half provide focused checks; `gentle-crosscolor` can produce the photographic expected bytes. The focused browser suite executes these fixtures, including the complete photographic output oracle. The closed-form oracle applies to these authored dyadic multilinear files, not arbitrary LUTs.

Targeted adjacent gates: source filters, Curves banks/Smooth, precise-color global/source ownership, filter blend/mask/Bake and recipe suites plus build. Exact counts and any discovery updates follow the final kind registry; do not change layer-blend counts or unrelated legacy controls speculatively.
