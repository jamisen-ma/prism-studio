## Accepted direction and numerical evidence

Root and architecture prefer a sole immutable original `.cube` asset and a strict new source/global kind, serial asynchronous table preparation, no persistent cache/library and explicit refusal of recipe definitions carrying LUT dependencies. The input policy is encoded-sRGB RGB8; file syntax cannot identify all log-intended normalized tables. Source/global alpha, source blend/opacity, deferred effect mask, Bake and geometry contracts remain as described in the reassessment.

Prefer Float64 samples over additional Q16 sample quantization. The independent probe `test-results/color-lookup-review/numeric-probe.mjs` imports neither the proposed parser nor any production transform. It uses exact dyadic samples and a separate BigInt result for100000 random eight-corner cases. Q16 changes49 output bytes; the selected Float64 accumulation changes none in this corpus. This is not a universal exact-real guarantee. A literal size2 red gain from0 to255/256 at input128 gives127.5→128 with original samples, but Q16 produces127.499992…→127. Keep this simple gain fixture permanently if the feature proceeds.

The proposed native order agrees with the independent probe: derive cell coordinates and remainders from integer `byte*(grid-1)` over255; form eight integer weights in red-fast order000,100,010,110,001,101,011,111; accumulate `sample*weight` in that order; divide by65025, clamp to0–255 and `Math.round`. All weights are nonnegative and sum255³. At byte255 choose lower cell`grid-2` with remainder255, keeping every corner index in range and evaluating the terminal vertex. The independent probe checks24576 Float64 identity outputs and24576 asymmetric channel-permutation outputs across sizes2–33, in addition to8192 Q16 identity checks.

The integer cell and weight calculations are exact: `byte*(grid-1)<=8160`, each weight<=16581375, and no corner index exceeds`3*33³-1`. Only parsed table samples, products/accumulation, division and final native rounding carry floating error. With samples in[0,1], there is no cancellation in the weighted sum. Identity table nodes approximated by binary64 `i/(grid-1)` introduce only tiny interpolation error; the final result stays far less than half a byte from the original integer input. Identity/permutation therefore round back exactly, without recognizing and bypassing an identity file. General authored half ties follow the declared native order and must not be advertised as exact rational rounding. A hand-authored approximate identity cube must not be silently treated as exact merely because its title says Identity.

Architecture proposes a33³ Float64 table862488 bytes plus a512-byte axis table, retained863000 bytes; that is reviewable without any extra image plane. Confirm actual compiled closure ownership and array backing sizes in the prototype. Parser proposal is4MiB original UTF-8, bounded4096-character lines,64-character number tokens and200-character title, all subject to strict grammar and measured cooperative preparation. These are not yet a production capability contract.

## Asset traversal and ownership gates

1. One kind-aware descriptor walker must cover global adjustments and source entries through legacy arrays or masked wrappers. Current `projectAssetUses` and bundle enumeration do not find parameter references. Every typed use of a shared hash must be compatible; source-document/raster validation must not be skipped when a LUT use is also present.
2. Gather references across all100 possible retained history states for restart verification, including hidden/disabled/history-only entries. Validate descriptors synchronously before reads, deduplicate compatible hashes and verify bytes serially. Root accepted a128-unique-hash/64MiB unique-original-byte history bound, enforced against prospective retained states at commit and at restart before reads. Apply history truncation before this count so ordinary pruning has its actual effect. A compiled-table cache is not necessary.
3. Bundle current-state transfer must include exactly the referenced LUTs, retain byte hashes, reject missing/extra/incorrectly typed assets and validate all payloads before any publication. A new kind gives old-reader refusal; a bundle-version bump is not automatically needed merely because a new asset use is added. Preserve current format/limits unless a separate structural incompatibility is found.
4. Atomic import+attach/replacement must own caller bytes at call time and perform target/revision checks inside the queue. A stale/invalid target must not publish a detached asset. Validate parse, descriptor, work and memory before commit; follow the existing owned-created-assets cleanup on actual save failure and late transaction rollback. Never unlink an existing deduplicated asset or one referenced by another history state/document.
5. Import/export/restart/reuse all require the same bounded verified reader and exact declared-byte match, not only a file suffix or a trustworthy-looking descriptor. Missing/corrupt files must fail without falling back to identity. Original source raster bytes and original LUT bytes both remain unchanged.

## Preparation and actual phase gates

`applyLayerFilters` currently owns a source input and working copy before its per-entry transform. A masked caller additionally retains its original for the final mix; Bake may retain original, effective alpha, decoded working and encoded inputs. Therefore parser bytes are added to the actual live image phase. They cannot be accounted as a separate passing limit with those buffers omitted.

`applyAdjustment` can prepare the table before allocating its output and own mask callback, but root/ancestor/clipping buffers may already be live. A clipping base callback can remain during a source member's parse. Tables from different entries must not survive sequential iterations; a Gaussian ring and a different entry's table use a phase maximum, whereas shared noise and already live ancestor callbacks are added separately. Deferred source-mask preparation remains after the entry helper returns.

A candidate parser component `3E+T` covers original BufferE, worst-case decoded UTF-16 text2E and tableT only if no complete token/line array or second full string is retained. It excludes bounded token/setup objects and already live caller buffers. After parser text leaves scope, the table plus512-byte axis buffer remains; a minimal2³ file can have3E<512, so the relevant component is at least`max(3E+T,T+512)`, plus any named bounded parsing allowance. Root accepted a separate32MiB original-byte preparation sum per nominal pass, counting every active positive-opacity occurrence even when hashes repeat. This bounds preparation independently of cheap tiny-image pixel work. Inspection/protection can re-evaluate a source, so describe whether the budget is nominal per graph pass or covers those repeats; do not claim a whole-render CPU bound without accounting them.

The final design must provide exact formulas and boundary fixtures for ordinary graph reserve, direct stack, full masked source, Bake filter/preparation phases and stronger Distort graph/leaf admission. Global preparation needs a serial global reserve at the graph peak. Existing global Curves table, positioned/ordinary callbacks and persistent noise must be combined according to actual simultaneity. Bundle/import transport payloads need separate ownership accounting. State these as named reachable-buffer bounds, not RSS or immediate garbage collection.

## Recipes and UI gates

The generic kind registry feeds recipe validation, so adding the kind alone risks accepting an untransferable local asset hash. Refuse LUT-bearing recipe slots/steps/definitions in shared validation and native normalization before I/O, including disabled source steps. The browser must explain why whole-stack capture is unavailable and require an explicit filter opt-out; never silently remove the LUT. Ordinary dependency-free recipe edits in a document already containing a LUT should remain supported where their bound target is otherwise valid.

Capability checks need the exact LUT policy and declared format/limits plus scope-specific commands. A saved unsupported entry should remain inspectable with honest filename/title, grid/bytes and encoded-input assumption. File chooser cancellation creates no asset or graph mutation. Hold/replacement/capability/document/target changes must invalidate old async completion through both metadata and preview phases. No public file title can imply a detected input color space. UI design is owned separately; no client change is proposed here.

## Joint global phase finding

The first proposed separate additional-scratch and direct-global checks do not establish a joint global peak. `test-results/color-lookup-review/global-phase-counterexample.json` records a metadata-only4096² example: one isolated group containing an active global grid33 lookup with a full-size ordinary feathered bitmap mask. Table+axis is863000 bytes. Additional`R(5N)+C(6N)+G(4N+table)` is252521240 bytes and direct`5N+4N+table+ownMask(5N)` is235744024 bytes, both below256MiB. However the root, isolated child, global output and own feather constructor are concurrently at least`19N+table=319630104` bytes. A combined conservative`5N+R+C+G=336407320` rejects before I/O.

This finding was sent to architecture and root before a design freeze. The actual bitmap callback allocates both its byte plane and a Float32 distance plane even for an all-white bitmap, so a single short RLE run reproduces the storage condition without a metadata-complexity confounder. No large buffers were allocated by the review. Close this with an explicit joint global graph phase; mirroring only the standalone global check into graph validation is insufficient.

**Resolved in the approved design:** any active-LUT graph admits`6N+Rmax+C+sharedNoise+max(Dmax,Gmax)+existingGlobalCurves1280`, with all content leaves included in Dmax and P inside source candidate maxima. Gmax is`max(P,4N+table+512)` across global lookups. This charges353184536 bytes for the counterexample and rejects; an unmasked plain24MP global lookup remains admitted at240863000 bytes. Existing Distort/legacy gates remain and legacy-only admission is unchanged. The named ledger explicitly excludes preexisting global spatial/style/codec/encoded-image internals and RSS.

The prototype now materializes TITLE independently through bounded UTF-16 code units; runtime preparation returns only the private transform after descriptor validation. Six independent empty/hash/Latin/astral-title endpoint cases pass, including exactly200 UTF-16 units and rejection above the bound. The final actual-prototype audit remains green after both strict decimal handling and title-copy changes.
