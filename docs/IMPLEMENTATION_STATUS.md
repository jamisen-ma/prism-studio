## Findings and disposition

- **Fixed by architecture:** retained results targeting existing documents now require a current `expectedRevision` for explicit application. An already succeeded receipt can still be replayed safely.
- **Fixed by architecture:** queue capacity now matches the advertised one active request and five waiting requests.
- **Fixed by root:** both paid MCP start tools require a caller-supplied stable request ID. Uncertain tool responses can be recovered using the same ID without silently creating another paid request.
- **Fixed by architecture, independently tested:** a failed running receipt halts dispatch without a restart loop or provider call. A later explicit request can resume after repair.
- **Fixed by architecture, independently tested:** every pending job reserves up to 32 MiB for output before a provider call, preventing predictable local storage exhaustion from discarding a paid result.
- **Fixed by workspace UI, owner browser-tested:** cancelled jobs containing saved output have an explicit Apply action that does not issue another provider request.
- **Fixed by workspace UI:** the optional API connection label says “OpenAI configured”; local key presence does not claim connectivity or available quota. The default label is “Codex conversation,” and only explicitly selecting the optional API checks its configuration.

- **Fixed by architecture, source-reviewed:** generate-as-layer forwards no provider mask or input image; provider masks are forwarded only for edits.
- **Fixed by architecture, source-reviewed:** generate jobs no longer save or apply capture-time protection masks. They can use current protected geometry after canvas changes; saved selection masks remain specific to edit jobs.
- **Fixed by architecture, independently tested:** explicitly protected generated layers retain normal stacking. Duplicating them no longer causes mutual clipping and a transparent composite.
