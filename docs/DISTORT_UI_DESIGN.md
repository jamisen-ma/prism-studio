# Four-corner Distort UI

Implemented per the approved native contract, 2026-09-19; the eight focused browser workflows, 51 adjacent workflows and build pass. Existing Move and affine Transform behavior remain separate.

## Retained stages and controls

Add **Distort layer** to the selected content layer’s inspector actions. It opens an inspector editing mode, rather than the existing blocking Transform modal, so the canvas remains available for corner handles. Eligible types follow the advertised native content-type list; groups and global adjustments are excluded. Protected layers remain inspectable but cannot add, update or remove a Distort stage.

The inspector lists every retained Distort in the full `transforms` array, in evaluation order. Each row shows its ordinal, full geometry-stage position and input/output frame dimensions. Selecting a historical stage opens its saved coordinates; editing and removal are not restricted to the final stage. **New distortion** appends a new stage after the complete saved geometry. The commands are `add_layer_distort`, `update_layer_distort` and `delete_layer_distort`, each with a positive captured `expectedRevision`. The update/delete index identifies the complete transform array, not the filtered Distort-only list. The argument is `transformIndex` (0–499), pinned to `expectedRevision`.

The strict record is `{type:'distort',width,height,corners:[TL,TR,BR,BL]}`. The fixed output frame equals the preceding stage’s dimensions. Historical stages retain their original frame even after later crop/resize/canvas stages; the inspector labels the fields **Stage coordinates, px** and displays that frame rather than incorrectly labeling them current canvas coordinates. New/trailing stages coincide with the current document frame.

Four rows—Top left, Top right, Bottom right, Bottom left—each contain X and Y fields. All eight values use independent string drafts, `step="any"`, finite values and the final authored coordinate bounds (±16384). Blank, incomplete, nonfinite or out-of-range values disable Apply. Numeric-equivalent spellings compare cleanly with exact saved Numbers; opening a stage never rounds or rewrites its coordinates. No snapping, clamping, integer conversion or ordering/sorting of corners is implicit. The backend remains authoritative for strict clockwise convexity, minimum span, conditioning and pole limits; a rejected quad remains editable in the inspector.

**Reset rectangle** replaces only the local corner draft with the exact identity rectangle for this stage’s frame, using outer pixel-edge corners `(0,0),(W,0),(W,H),(0,H)` in TL/TR/BR/BL order. **Revert draft** reloads the selected saved stage; for a new stage it restores its initial rectangle. **Apply distortion** adds or updates one saved stage and creates one Undo step. **Remove saved distortion** removes only that stage and reevaluates following geometry; it never silently applies the visible draft. Resetting corners is distinct from removing a stage. An identity-shaped retained stage may have different resampling/resource semantics from absence; the UI must not silently delete it.

## Canvas handles and honest preview

For a new appended stage or an existing trailing Distort, show the draft quadrilateral and four labeled corner handles above the current saved canvas preview. The guide is an outline only: **Draft guide · pixels update on Apply** remains visible. The saved image is not CSS-warped or treated as a native pixel preview. General projective sampling uses the declared bounded native binary64 semantics; do not claim exact-real or Adobe pixel parity. Identity and integer translation have explicit exact-RGBA special paths. The fixed clipping frame has a separate subdued outline. Help explains that image content outside this stage’s frame is clipped during evaluation. Revisiting this Distort can recover content clipped by this Distort itself while its prior-stage input remains unchanged; it cannot recover pixels already clipped by an earlier crop/canvas stage. Original source bytes and geometry records remain retained, but later geometry may still clip the revised result.

When a saved Distort has later geometry, keep all eight numeric fields and Remove available, but omit its on-canvas handles. Show **This stage precedes later geometry. Edit its stage coordinates numerically; canvas handles are available for the final stage.** Raw historical corners must never be drawn as current canvas positions. A future projection implementation would need proof for the entire suffix, including intermediate clipping and singular cases; it is outside this increment.

Each pointer gesture captures one pointer ID, editor epoch, selected stage, document/backend/layer/revision, frame dimensions and canvas rectangle/zoom. Convert viewport positions into that captured stage frame with floating-point coordinates; do not round or clamp. A handle drag changes only its own X/Y strings. Release keeps the local draft without sending a command; Escape/pointer cancellation restores the pre-drag pair. Foreign pointer events cannot move the active handle or clear its state. View geometry changes, lost capture, navigation, stage change and capability withdrawal cancel only the owning drag. Cleanup from an older gesture cannot erase a replacement draft or guide. Exiting the inspector mode removes its guide and pointer interception immediately, restoring ordinary tools.

Handles use visible focus states and at least 24px interaction targets; numeric fields provide equivalent keyboard operation. Off-frame coordinates remain readable/editable and are never moved to the edge by the UI. Where an off-frame handle is outside the visible canvas, numeric editing remains available with a short off-frame notice. No document resizing or automatic fit-to-quad occurs.

At a 900px-wide workspace, the inspector uses a two-column X/Y grid, short corner headings, one compact fixed-frame notice, Apply and Remove, plus collapsed **How Distort works** details. The details distinguish Distort from Move/Scale, explain source filters before geometry, unchanged document-space masks/selection/guides and frame clipping. The new mode must not require a horizontal inspector scroll. At narrower responsive layouts, the same numeric panel remains fully operable even when canvas handles are unavailable.

## Capabilities, ownership and refusal

Require `layerDistortPolicy:'fixed-frame-projective-bilinear-v1'`, `layerDistortCoordinates:'stage-pixel-edges'` and the selected type in `layerDistortContentTypes`. Validate the finite positive integer corner/work/working-byte limits against the policy ceilings (16384, 384M and 256 MiB). Add/update/delete command gates remain independent: an update-only companion can revisit supported saved stages, a delete-only companion can explicitly remove them if its semantics are advertised, and unsupported saved stages remain readable. Unknown/malformed capability values fail closed. Do not infer support from the old affine command or silently replace Distort with an affine approximation. The complete capability signature includes all three fields, all three limits, commands and connection state.

Capabilities participate in submission identity, not the draft key. Withdrawing a policy/command preserves the eight draft strings and stage selection, disables the affected action and cancels an active pointer gesture. Restore support without resetting those drafts. Hidden content is numerically editable when allowed by native protection rules; handle usefulness can be explained without falsely banning saved-stage editing solely for invisibility.

Use a stable inspector controller with an editor epoch and explicit captured stage identity: backend, document ID, expected revision, layer ID, full transform index (or append), frame and saved stage fingerprint. Selecting another document/layer/stage, closing/reopening the mode or changing relevant capabilities invalidates pending UI ownership. A revision change never silently retargets a historical index. Preserve a stale draft as stale and disable its old stage rows. **Reload current geometry** explicitly discards the draft and rebuilds the list. If the transforms changed, open a new draft so the user must choose a saved stage again; never silently retarget an old index. Do not replay an operation automatically.

The new commands need narrow App response and preview gates, like the existing guarded filter/mask paths. Validate the captured context before dispatch and before installing a response; validate response document/backend/revision and expected target stage transition. Then explicitly acknowledge the owned revision transition before publishing metadata, so an own-success update/removal does not invalidate itself through the changed index or fingerprint. Recheck ownership before installing the asynchronous preview and before local completion. Removal selects a deterministic remaining stage only while that same editor still owns the result. An old successful response must never reopen a closed editor, change the selected layer/stage, replace a newer preview or clear a replacement draft.

Handle `REVISION_CONFLICT`, protection, invalid quad and resource refusals without automatic retries. Keep invalid/resource-refused drafts and the original saved graph. Any fresh-document reconciliation is guarded at both response and preview stages; away-and-back navigation does not revive an earlier epoch. Source assets are never generated, rewritten or baked by the UI. Reset/Revert/drag produce no history or commands. Retained Distort editing and Undo/Redo operate on metadata; normal rendering remains native.

Source filters and their source effect mask run before Distort. The additional layer mask, selection and guides remain document coordinates. Existing source-selection capture refuses geometry containing Distort rather than inverse-resampling a selection. The UI should surface that existing native reason, not remove the stage or materialize pixels automatically. Explicit rasterization/painting behavior follows the finalized geometry contract and existing source-edit rules; no promise of editable stages after a deliberate rasterization.

## Eight bounded browser acceptance workflows

1. Add a new rectangle, edit exact fractional/scientific numeric drafts, verify equivalent values are clean and invalid fields dispatch nothing. Reset/Revert stay local; Apply sends the exact approved corner order and adds one Undo step.
2. Drag all four trailing-stage handles at multiple zooms without early writes; verify release only changes draft, explicit Apply changes pixels, cancellation restores the prior draft, off-frame coordinates are retained and foreign-pointer/layout changes cannot corrupt ownership.
3. Revisit an earlier Distort before later crop/resize/affine stages. Numeric update and remove change only the indexed stage, preserve suffix records and source bytes, omit misleading historical handles and survive Undo/Redo/reopen.
4. Exact/missing/unknown policy, eligible types, malformed capability lists and independent add/update/delete partitions. Saved unsupported records stay readable; capability withdrawal preserves drafts and disables execution; protected records cannot mutate.
5. Delayed add/update/remove, selected-stage/layer/document changes, mode close/reopen and capability loss before and during preview. Own updates/removals complete normally; stale successes/errors/cleanup never install or retarget. Exercise revision conflict plus guarded reconciliation without replay.
6. Backend-owned exact pixel fixtures for identity, translation, asymmetric perspective, mixed alpha and clipping; compare preview/export at the native seam and retain original assets. Distortion affects content geometry while document-space masks/guides/selection retain their defined scope.
7. Invalid convexity/pole/work refusal retains draft, graph, assets and history. Source-filter mask capture rejects Distort with an actionable reason. Explicit rasterization/painting, if supported by the final contract, discloses that it consumes the retained geometry rather than silently baking it during editing.
8. A real maintained photograph mapped to an asymmetric quad; 1440/900 screenshots with numeric fields and Apply reachable, guide/help truthfulness, portable/restart/Undo behavior and zero provider/key calls. Regress adjacent Move/affine/canvas-resize/mask/source-filter and geometry consumers identified by the backend audit.

The frozen commands/capabilities are implemented. `INVALID_ARGUMENT`, `INVALID_TARGET`, `NOT_FOUND`, `PROTECTED_LAYER`, `LIMIT_EXCEEDED` and `REVISION_CONFLICT` surface native refusal without retries. ## Reviewed implementation details

The independent source review identified three concrete risks that were corrected: corner grabbing now retains the pointer-to-corner offset and preserves unchanged numeric strings; entry checks existing canvas/pan capture ownership; all three advertised limits are validated. Opening/closing or selecting a saved stage while a command is busy remains a local inspection action. Fields and mutation controls remain disabled, and the replacement editor advances its ownership epoch so an older response cannot install into it.

The parent review additionally identified stale stage rows. They now stay disabled until explicit reload, and a changed geometry list requires choosing a saved stage again. Browser cases cover off-center handle clicks without movement, external stage deletion, blocked entry during brush capture, foreign pointers, Escape, view changes at pointerup and capability withdrawal during a drag. The guide and other tool overlays are mutually exclusive while the editor is active; exiting restores normal tool behavior. Protected-cutout help now distinguishes allowed additional masks/old Move/Scale controls from Distort.
