## Shared control and exact drafts

Add **Selective Color** to global adjustments and source filters, with `kind: 'selective_color'` and `value: 0`. This makes 25 global kinds and 29 source kinds without new commands. Use one shared `SelectiveColorControls` component and a pure client helper for effective defaults, draft conversion, parsing, canonical comparison and capability checks.

Parameters contain `method: 'relative' | 'absolute'` and nine rows, in this order: `reds`, `yellows`, `greens`, `cyans`, `blues`, `magentas`, `whites`, `neutrals`, `blacks`. Each row is a four-element Cyan/Magenta/Yellow/Black tuple. New controls default to Relative with all36 values zero. Reading sparse persisted parameters fills only absent fields with these effective defaults, without a mount write; rows are separately copied.

The parent owns all nine four-string rows and method, not only the visible row. A keyboard-accessible **Color range** select chooses the visible row. Changing range or method preserves every other exact draft string, including incomplete strings. Four compact percent controls expose Cyan, Magenta, Yellow and Black; use text inputs with decimal input mode so `1e`, blanks and scientific forms are preserved. Optional range sliders are merely deliberate authoring conveniences and must not normalize values on mount or range selection. Numeric precision is authoritative; no slider is required for this first slice.

Parse strict finite decimal/scientific strings in −100..100. Accept exactly `Math.round(value * 100) / 100 === value`, with no tolerance or silent rounding; canonicalize negative zero. Parse all36 values even when their range is hidden. Any invalid row disables Apply and is named in the validation message/selector, so the user can locate it and correct it. Equivalent strings such as `12.50` and `1.25e1` are clean against saved12.5. Range selection remains usable for inspection/correction when another range is invalid or the saved entry is unsupported; disabled numeric fields do not prevent reading other rows.

**Reset range** changes only the current row to four zero strings, preserving method and other rows. **Reset all** restores Relative and all-zero rows. Both are local operations and preserve source filter opacity/blend and the attached mask. Invalid strings may be repaired with either reset. Read-only/protected/busy controls cannot mutate drafts; command-only partitions may still use local controls/resets, but cannot submit a missing command. Range inspection itself does not invalidate an otherwise owned result.

Apply sends the complete canonical method and all nine numeric tuples, never only the visible row. Native partial-update behavior remains available through MCP, but the UI's complete payload makes hidden-range intent explicit. Saved sparse and complete all-zero records open clean. All-zero settings remain a valid user-authored adjustment/filter and an identity candidate; they must not be rejected as an empty edit when adding a new record.

## Product explanation and compact layout

At 900px, the shared controls should show Method, Color range, four labeled numeric percentage fields, Reset range/Reset all and concise help; source blend/opacity/Apply remain nearby. All controls are keyboard reachable and have range-specific accessible names such as “Reds cyan percent.” Show the range name in validation rather than relying only on color swatches. Reuse the existing dark field styling and sufficient control height; do not present36 fields simultaneously.

Always-visible copy: **“Adjust selected color ranges in the input RGB. All range settings stay together.”** The global/source parent continues to explain its selection/mask scope. Put the following in collapsed **How Selective Color works** help:

- This is Prism's native RGB correction, not a print CMYK conversion or an Adobe pixel-parity mode. Nearby ranges can contribute to one pixel, using that entry's original input colors.
- Positive Cyan/Magenta/Yellow reduce the corresponding Red/Green/Blue contribution; negative values move the opposite way, subject to clipping.
- Black adds the same signed virtual-ink contribution to all three corrections. It is additive, not extracted physical black ink; opposite Cyan and Black cancel only the Red correction.
- Relative scales existing complementary amounts. It cannot change pure white, and positive Black can leave a fully saturated primary unchanged. Absolute can add correction at white or darken such a primary. Switching method keeps every row; preview the result after Apply.
- Both paths preserve alpha and fully transparent source RGB. Source entry blend/opacity and the whole-stack mask apply in their existing order. All-zero controls are only an identity candidate: nonnormal filter blending can still change pixels, and the saved entry still participates in source-edit/protection guards.

Use actual native previews/exports after Apply. No synthetic RGB swatch approximates the combined ranges as if it were an authoritative image preview. Global histogram remains the existing optional read capability.
