# Linked Perspective controls

Status: **implemented and accepted**, 2026-09-19. Layer Fill is complete at 67 browser workflows plus build. This proposal extends the existing Distort controller; it introduces no renderer, native command, persisted mode, capability, asset or recipe step. It follows [the helper/native design](LINKED_PERSPECTIVE_DESIGN.md) and [independent review](LINKED_PERSPECTIVE_REVIEW.md).

## Small explicit workflow

Keep the existing **Distort layer** entry, retained stage list, eight corner coordinate fields and **Apply distortion** action. Add one **Corner movement** selector with **Free corners**, **Horizontal perspective** and **Vertical perspective**. Free corners remains the default each time a new or retained stage is opened. The selected movement mode is local authoring state; it is neither inferred from an existing quadrilateral nor persisted in the stage.

The linked modes control canvas drags and a separate **Move pair** action. The existing eight coordinate fields always edit independently. A short visible explanation states this distinction. Mode changes alone never move a corner, send a command or create history.

Horizontal perspective changes only X: Top left ↔ Top right, Bottom right ↔ Bottom left. Vertical perspective changes only Y: Top left ↔ Bottom left, Top right ↔ Bottom right. These are the stage's axes, including for rotated or skewed quads. Corner identities retain their TL/TR/BR/BL ordering; no sorting, rectification, rotated edge basis or camera inference occurs.

In either linked mode, show a compact **Selected corner** selector, an exact **Delta X, px** or **Delta Y, px** text input, **Move pair**, and **Clear delta** when needed. A helper line names the partner and the affected axis, for example “Top left ↔ Top right · opposite X movement.” The exact authored delta remains visible in its field; an incomplete delta never invents a numeric result. Enter in the delta input performs the same local Move pair action. The visible scope is **Changes the draft only. Apply distortion saves the displayed corners.**

The delta input starts at `0`. A successful explicit nonzero Move pair resets only this input to `0`; the resulting corner draft stays visible. This prevents an accidental second click from applying the same offset again. An exact zero action is clean/disabled and leaves every coordinate string untouched. **Clear delta** discards only the unapplied delta and leaves the current corners intact; while idle and not dragging it remains available even when authoring support is withdrawn or the saved revision is stale. Reset rectangle and Revert draft explicitly reset the corner draft and delta together; closing retains the existing explicit editor-discard behavior. Choosing another stage first requires Move pair or Clear delta when a delta is pending.

A nonzero or invalid/incomplete unapplied delta blocks **Apply distortion**, with a short instruction to Move pair or Clear delta. It cannot be silently ignored by a server submission. Movement mode and selected-corner changes are disabled while this delta is pending or during a drag/command. Retained-stage changes are disabled during a drag or unresolved delta, while existing read-only stage navigation remains available during a command; Clear delta remains the simple local escape. Independent corner fields remain available when otherwise editable, and Move pair captures their current valid quad at the moment of the deliberate action. Capability withdrawal retains both the corner strings and pending delta; it does not apply, clear or reinterpret either.

## Exact numbers and bounded candidates

Both pointer movement and Move pair call the same `shared/linked-perspective.mjs` helper using `{cornerIndex,axis,delta,limit}`. The frozen helper delta bound is finite `abs(delta) <= 2 * limit`, where `limit` is the valid advertised Distort corner limit. From the captured original selected value `s` and partner value `p`, evaluate exactly `s + delta` and `p - delta`, in binary64. Never reconstruct a midpoint or accumulate from previous pointer events. The helper owns its returned points and reports whether the complete candidate fits native corner bounds.

Keep the six untouched coordinate strings exactly. Preserve an affected coordinate's original string when its computed Number is unchanged, including a tiny movement swallowed by ordinary binary64 rounding. A zero active-axis delta returns the full original draft, including scientific notation and signed-zero spelling. Opposite displacements preserve the mathematical midpoint; the interface makes no exact floating-point midpoint or separate-gesture reversibility promise.

The new delta input is `type="text"` with decimal input mode, not a browser number control that sanitizes `1e`. Parse the complete decimal/scientific grammar, reject nonfinite/range-invalid strings and lexical nonzero underflow, and allow literal/scientific signed zero. Do not round, clamp or apply an arbitrary minimum step. Existing direct fields keep their independent behavior; any narrowly necessary text-input correction should preserve their current full-string parser and finite corner limit rather than add linking to them.

For a helper-bounded delta that puts a corner outside native bounds, **Move pair installs both computed values as the complete local invalid draft**. Both values remain visible, no coordinate is clamped, and Apply is disabled. Existing direct fields, Reset rectangle and Revert draft correct it. A crossed or otherwise unstable but in-range quad can likewise remain a draft; native convexity/pole/work checks remain authoritative on Apply.

A numeric delta outside the helper bound remains raw invalid text and changes no corners. During a pointer drag, exceeding the helper bound cancels the owning drag, restores its exact captured draft and reports the reason. This deliberately avoids a last-valid guide with an unrepresented pending movement. The ordinary helper-bounded but native-out-of-range candidate can remain visible through release just like a free-corner overshoot. The guide is never a CSS image warp; native pixels still change only on Apply.

Root, architecture and independent review have agreed these recovery rules. Helper-bounded invalid candidates remain one complete local quad; over-helper-bound pointer movement cancels the gesture. Keep guides within the normal clipped canvas viewport so the possible three-times-limit coordinates cannot create page or inspector overflow. Root released implementation after the final independent conceptual review. The out-of-bounds numeric values persist after release; the existing guide may disappear when its bounds parser rejects them.

## Session and pointer ownership

Extend `Session` in `client/Distort.tsx` with the movement mode, selected pair corner and delta string. Opening/reloading a new or saved stage defaults to Free corners, Top left and zero delta. A successful Apply acknowledges the exact returned stage through existing `distortResultMatches` before metadata publication, retains the local mode/corner for continued editing and uses the acknowledged complete corners as the next baseline. A successful Remove discards the removed stage’s corner/delta drafts and initializes the chosen remaining/new stage with Free corners, Top left and zero delta; a failed Remove retains the draft. Mode and delta are absent from all command payloads and metadata.

At pointerdown, capture the mode, corner/partner/axis, all eight baseline strings, parsed baseline quad, pointer ID, current session epoch, target/stage/revision, exact capability signature, fixed frame and displayed rectangle. The existing off-center grab rule stays intact: active-axis displacement is measured from the actual captured pointerdown position. Orthogonal-only motion and return to the original active-axis position preserve the exact baseline strings. Every move evaluates from that baseline, so event density cannot accumulate drift.

Mode/corner switches are disabled and their handlers refuse changes while a drag owns capture. At move and pointerup, check the captured owner against live target, stage, revision, capabilities, view geometry and busy state before changing the draft. Busy beginning during a gesture cancels it; the current hook's busy check only at pointerdown must be tightened at the shared drag seam. Escape, pointercancel, lost capture and view changes restore the exact baseline only if that same editor still owns it. Foreign pointers cannot move, cancel or release the owner's capture. Older cleanup cannot restore over a replacement session.

The existing controller already guards target/capability epochs, selected historical indices and native result/preview installation. Keep these gates and its explicit own-revision acknowledgement. No generic App runner, retry or reconciliation rewrite is needed. Retained-stage inspection remains allowed during a pending command when no local delta is unresolved. Close is always an explicit whole-editor discard, including an unresolved delta; they invalidate old ownership. New mode, delta and corner mutations are busy-disabled. A held old result or preview cannot reopen a closed editor or replace a newer draft.

The existing display rectangle/frame mapping is captured once and checked again at pointerup. New/trailing-stage handles use that truthful current frame; historical stages before later geometry still have **numeric-only** editing, including Move pair in their original stage axes. Never draw historical corners over the final image or silently append a new stage when updating one in the middle.

## Existing capability, pipeline and accessibility boundaries

Use the existing native Distort policy, coordinate marker, selected content type, advertised bounds and independent add/update/delete commands. No linked-mode marker is needed because all resulting records are ordinary supported Distort stages. While touching the support helper, validate a connected Native backend and an all-string command array before membership checks; a malformed string containing a command must not grant authoring. Preserve currently accepted known selected-type subsets and lower valid numeric ceilings. Unsupported saved stages remain readable; independently supported Remove keeps its current protection/revision rules. Protected layers cannot mutate corners or paired drafts.

All native pipeline behavior remains unchanged: source filters and effect mask before geometry; document-space layer mask/selection/guides afterward; existing fixed-frame clipping, source retention, Fill, styles and portable project behavior. Revisit/remove remain genuine retained-stage operations. No automatic rasterization, canvas enlargement, filter-mask inversion, approximate warp, camera correction or Photoshop pixel-parity claim is added. Existing native errors surface without automatic retries.

Use the established 32 px dark fields and theme tokens. At 900 px, keep the mode selector full-width, corner/delta controls compact, the eight X/Y fields in their existing two-column rows, and Apply/Remove reachable through ordinary vertical inspector scrolling. New guidance is one short always-visible line plus additions to the existing collapsed **How Distort works** disclosure. Do not add a second modal or duplicate all geometry help.

The mode, selected corner, delta, Move pair and Clear delta are labeled native controls with visible focus and logical keyboard order. In Free corners, activating a canvas handle by Enter/Space retains the existing focus-on-that-corner-X behavior. In linked mode, activation selects that corner and focuses its delta field only when no pending delta/drag or mutation blocks it; otherwise it focuses the existing pending delta and explains Clear/Move first. Ordinary pointer drags never steal keyboard focus. Live validation/cancellation status is concise and does not expose implementation details in the normal editing flow.

## Eight focused browser workflows

1. **Explicit modes and exact paired actions.** Default Free, no writes on mode changes; all four corners under each axis; positive/negative/fractional/scientific/zero delta; six exact untouched strings and unchanged affected strings. Move pair is local and resets only delta; Apply sends the ordinary complete corners with one revision/Undo.
2. **Precise pending and invalid drafts.** Incomplete `1e`, nonfinite, lexical underflow and helper-out-of-range strings; nonzero pending delta blocks stage Apply until Move/Clear. Direct fields remain independent. Helper-bounded out-of-corner-range candidates show both exact values without clamping; Reset/Revert and native geometric refusal preserve recovery.
3. **Captured pointer arithmetic.** All pairings, off-center grabs, two zoom levels, orthogonal-only and return-to-start motion, direct-final versus many intermediate samples. No server writes before Apply. Beyond-helper-bound movement cancels/restores with notice.
4. **Pointer ownership.** Foreign pointer IDs, Escape, lost capture, mode/corner/stage switch attempts with an unresolved delta, busy transition, view change at pointerup, capability withdrawal/restore and stage/layer/document changes. Old cleanup never overwrites a replacement session.
5. **Retained geometry and exact native equivalence.** Apply linked corners and manually authored identical corners to independent copies and compare records/decoded pixels. Update/remove a middle stage with later affine/resize records, numeric-only historical Move pair, Undo/Redo and portable reopen; source assets remain byte-identical.
6. **Capabilities/protection.** Independent add/update/delete partitions, malformed commands/limits/type lists, offline/unsupported saved inspection, lower corner bound and protected stages. Restore support without losing exact corner/delta strings; no new command/capability count.
7. **Held native responses/previews.** Normal owned add/update/removal, target/stage/editor/capability away-and-back, stale revision and guarded refusal. Local mode stays stable after an accepted success; old replies cannot retarget or reopen the editor. Existing ordinary Distort Apply remains the only pixel mutation.
8. **Actual photo and access.** Original maintained photo, horizontal narrowing, vertical narrowing and an arbitrary skewed baseline; original file SHA unchanged. Keyboard Move pair/handle focus, 900/1440 normal/help views, truthful draft guide, no overflow, browser errors, key reads or provider calls.

The bounded adjacent set is existing Distort8, Move4, pointer-capture4, canvas-bounds4, resize-resampling8, filter-mask8, mask-position8, cutout7 and the just-closed Fill8: **59 adjacent workflows**, or **67 total** including linked Perspective, plus build.
