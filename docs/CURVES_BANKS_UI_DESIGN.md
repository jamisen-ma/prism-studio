## Explicit representation, familiar editor

Keep the existing Curves kind, value0, commands and default single-curve editor. Native kind counts remain26 global and30 source. Opening an old record never upgrades or rewrites it. Its existing Channel selector continues to mean which channel the one point set affects; it must not be relabeled as a selector between independent saved curves.

Offer **Upgrade to channel banks** only with complete bank support. This is a local draft action followed by the normal Add/Update/Apply button, not an immediate command. The current valid single draft is copied exactly into Master for RGB or the matching Red/Green/Blue bank. The other three banks receive independent Linear identity point lists. Keep the copied interpolation and every authored coordinate/string. Select the bank that received the old curve. Existing blend, opacity, masks and geometry remain unchanged. The explanation is: **“Keep this curve and add independent Master, Red, Green and Blue curves.”** Invalid single drafts must first be corrected; there is no silent defaulting of invalid points. If the user already changed the single draft, the upgrade preserves that draft's intended mapping, not necessarily the last saved image.

In bank mode, show a **Curve bank** selector with **Master, Red, Green, Blue**, one existing graph and precise point editor. This selector changes inspection only. Each bank retains its own points, interpolation and selected point index. There is no editable channel field inside a bank: Master corresponds to RGB, and each component is fixed by its bank name. Use familiar per-bank colors plus text labels; selection and validation never depend on color alone.

Use the compact explanation **“Master runs first; each color curve maps its result. Apply saves all four curves.”** Interpolation applies to the selected bank only. Add point, numeric Input/Output, point selection and deletion retain their existing keyboard behavior. **Reset this bank** restores that bank's Linear identity only. **Reset all banks** restores four independent Linear identities and retains bank mode. Both actions remain local and preserve filter blend/opacity and attached masks. The parent global Reset must use the current representation: it resets all banks when banked and must never implicitly collapse to the old single format.

## Deliberate return to one curve

Do not offer an ambiguous mode dropdown that discards three banks as a side effect. Put the less common reverse operation in collapsed **Replace with one curve** controls:

1. **Keep bank** explicitly chooses Master, Red, Green or Blue; use a placeholder until the user chooses, rather than defaulting silently.
2. Show **“Use only the chosen curve. The other three curves will be discarded when you Apply; the combined result is not preserved.”** If Master is chosen, the replacement is one RGB curve. A chosen component becomes one curve affecting that component only.
3. **Use only this curve** stages the chosen exact point strings/interpolation in the single editor. It submits nothing. Mark the draft **“Single-curve replacement pending Apply”** while the saved representation is banked.
4. Normal Apply sends explicit `mode:'single'` and the complete chosen single parameters. Successful application is one Undo step; Undo restores all saved banks.

A local **Restore bank draft** action restores the exact four-bank snapshot that existed before downconversion while that unsaved replacement is being edited. It is scoped to the same document/revision/entry and discarded on external context change or successful Apply. It must not mutate saved state or silently merge single edits back into the stored banks. An upgrade from a saved single curve similarly offers **Return to single draft** before Apply using its captured original local draft. This avoids forcing users to reload just to undo a local representation choice. These recovery actions, conversions and resets are disabled while busy or dragging.

Conversion requires valid complete source settings and the semantic support for the saved representation. An unsupported banked entry is inspectable, not a loophole for silently dropping an unknown mode. Independently advertised Delete/Clear/Bake retain their existing removal rules. No curve fitting, composed-point approximation or promise of lossless arbitrary bank-to-single conversion belongs to this slice.

## Complete exact drafts and payloads

Use a discriminated draft rather than extending the single record with optional overlapping fields:

- Single: the existing channel, interpolation and exact point strings.
- Banks: four separate objects, each owning interpolation and 2–16 point string pairs; the inspected bank and per-bank point selection are local UI state, not submitted fields.

All bank arrays are independent copies. Reading effective defaults or selecting banks never shares caller arrays, writes metadata, changes representation or canonicalizes text. Validate every bank for Apply, including hidden banks. A hidden invalid bank is labeled in the selector and named in the error message; the selector stays usable to reach it. Suppress only the invalid selected bank's plotted line, with its actual strings still visible. Keep valid other banks available for inspection without pretending the whole draft is valid.

Each point uses the accepted finite decimal/scientific text parser,0–255, strict increasing X, endpoint X0/255, no minimum gap and no rounding. Preserve incomplete `1e`, equivalent scientific spellings, subnormal/adjacent X and every untouched coordinate. A Y-only numeric edit must not shift X. Existing graph authoring quantizes only axes that actually move; if no whole-unit X fits its strict neighbors, retain the original exact X. Keep the keyboard Add point midpoint action and16-point cap independently per bank.

Canonical comparison parses all four banks and treats each explicit Linear bank as its canonical bank representation. An untouched bank record is clean; a single-to-bank upgrade is a representation change even when pixels are unchanged. All identity banks remain structurally active. UI Add/Apply sends complete `{mode:'banks', banks:{master,red,green,blue}}`, each bank with the complete numeric point list and explicit `linear` or `smooth` interpolation. No top-level legacy points/channel/interpolation accompany it. This complete UI payload avoids inheriting stale hidden settings through the backend's bank-specific merge behavior.

Ordinary single edits keep their existing payload and canonical omission rules. Smooth→Linear needs the existing explicit interpolation reset. A bank-to-single Apply additionally includes transient `mode:'single'`; omission must never be used to infer collapse. Native normalization removes that discriminator from the saved legacy representation. Banked canonical metadata retains `mode:'banks'` even for four identities. The native partial-update contract requires explicit `mode:'banks'` for any nested bank patch: omitted banks and omitted fields retain their current values, while a supplied points array replaces that whole list. An empty parameter object is a no-op. Explicit `mode:'single'` on an already-single target remains an ordinary partial merge. These rules belong to the native merge helper, not a client shallow spread.

## Truthful graph and native composition

Show the selected bank's transfer function, not a mislabeled composite of all four curves. Legacy single Linear retains its authored-point polyline and single Smooth retains its accepted byte plot. In bank mode, the shared `compileCurvesBankLookup(spec)` supplies the selected bank's actual256 byte samples for either interpolation, with fractional authored knots marked separately. The native helper also exports `compileCurvesBanksLookup(parameters)` for the768-byte composed result; a selected-bank chart must not mislabel that composed result as one bank. There is no second interpolation implementation or SVG smoothing approximation. Reuse the existing composite histogram only as a labeled reference; it is not the computed histogram entering a component bank. The component Input value is the byte after Master.

The native candidate is Master byte lookup followed by the matching component byte lookup. For red it is `redLut[masterLut[r]]`, and likewise green/blue. Entry blend and opacity act once on the resulting candidate, followed by existing effect-mask and visibility behavior. The graph does not preview those masks or blends. A single Master curve with identity components, or a single component with identity Master/other components, preserves the legacy mapping for that curve's chosen interpolation; arbitrary four independent entries with separate opacity/blend/masks are not equivalent.

Collapsed **How channel banks work** help explains the two-stage byte lookup, each bank's input, all-bank Apply, explicit conversion and the existing Smooth-versus-Linear half-tie distinction. It must not claim Photoshop byte parity, exact-real interpolation, restored clipped detail or arbitrary lossless collapse. Source filters preserve alpha and skip hidden alpha-zero RGB. Global Curves keep their existing different hidden-RGB behavior; adding banks must not change that native policy. Identity banks may still change pixels through a non-Normal filter blend.

## Capability and inspection boundaries

The accepted capabilities are `curvesBanksPolicy:'master-byte-then-channel-byte-v1'` and `curvesBankNames:['master','red','green','blue']`; there is no separate mode list. Require matching Native, the exact marker, a well-formed string array containing all four recognized names, and the current context's Curves kind and command support; source additionally requires source coordinates. Bank capabilities are independent of Smooth: all-Linear banks require bank support but not the Smooth marker, while any Smooth bank, including a hidden bank, requires the existing exact native Smooth policy/mode. Existing single Linear needs neither new family. Single Smooth retains its current Smooth-only gate.

Inspect all four banks for authoring, source enabling/reorder and recipe execution. A saved unsupported bank or hidden Smooth bank freezes entry mutation rather than converting or disabling it automatically. Keep bank and point selection usable for read-only inspection under missing policy, malformed/partial lists, protection, missing mask/blend support, command withdrawal and busy Apply/preview. Show the specific unsupported bank/mode in the explanation. Preserve exact draft strings and the inspected bank when capabilities disappear and return.

This requires a narrow banked-Curves exception to ancestor disabled fieldsets, like the accepted HSL/Selective range inspection path. Every mutable control remains explicitly guarded: interpolation, graph, point fields/add/delete, resets, conversions, new-kind/mode controls, blend, opacity and Apply. Do not broaden unrelated legacy fieldset behavior. Keep a saved banked global Curves inspector mounted when `update_adjustment` disappears so inspection and existing exact drafts survive; Apply still requires the exact command. Local resets/drafts in add-only/update-only partitions follow the existing command-versus-semantic support distinction, while unsupported saved semantics remain read-only.

Delete/Clear and separately advertised Bake keep independent guards and scope disclosures. Bank policy/list fields join the existing Curves capability signature in global, source-entry, whole-stack and recipe contexts. The capability signature stays outside the draft key. Unknown strings may accompany a complete recognized capability set; mixed nonstring lists or an incomplete required set authorize no bank mode. These names are frozen; new unknown string names may coexist with the required four.

## Pointer and pending-result ownership

Reuse the current captured SVG screen CTM/inverse, pointer ID, owner epoch, pre-drag string snapshot and unchanged-axis behavior. The graph is bound to the selected bank identity as well as document/backend/revision/entry. Avoid a cross-bank restoration refactor in this bounded feature: **disable the bank selector while a graph drag is active**, and guard its handler as well. Point selection, interpolation/conversion/reset handlers either follow the existing exact cancellation path or stay disabled until the gesture ends. A foreign pointer cannot finish the gesture. Escape/cancel/lost capture, view change, busy transition and capability/context change restore the originating draft only while its owner still matches; old cleanup cannot overwrite a new entry or bank.

Bank selection is intentionally absent from the whole-Curves submission identity. The request contains all banks; inspecting another bank while its result or preview is pending must not reject a valid own completion. The selected-bank identity is present only in the local pointer/draft-rendering ownership. Preserve bank inspection through an own successful revision install where practical; do not confuse a revision-keyed editor remount with an external target switch.

Keep the existing `preciseColor` entry/target/kind epochs, actual toggled-row kind, accepted own-document handoff, empty-document first selection, and pre/post-preview/catch guards. Target/filter/kind or capability away-and-back cannot revive old success. Global/source bank selection alone does not increment those request epochs or mutate drafts. A current work/validation refusal preserves exact strings for explicit retry; revision conflict refreshes authoritative state without automatic replay. The native resource policy is authoritative, and the client never reduces a bank or resubmits a simpler representation after refusal.

## Recipes and scope

Capture the complete effective saved bank representation: four point lists and explicit interpolations. Ignore local bank selection, pending conversions and unsaved point strings. Definition capture/import remain inert operations available on companions unable to execute the bank semantics, subject to native schema/save-command support and existing mask-capture restrictions. This does not authorize editing, enabling, reordering or executing an unsupported saved entry. Execution requires support for every bank and current bound banked target; hidden Smooth cannot be ignored.

Complete bank recipes reset all target banks, regardless of sparse native partial-update support. Legacy recipe serialization/hashes stay unchanged. Native execution supplies the transient `mode:'single'` and explicit Linear reset needed to apply an old single recipe to a banked target; the UI must not mutate an old definition just to add those execution-only flags. Source recipes append complete fresh entries. Existing masked-stack capture refusal, explicit Filters opt-out, masked destination append, same-session deduplication and restart reconciliation remain unchanged.
