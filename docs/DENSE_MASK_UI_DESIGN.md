## Small useful workflow

Add a compact **From composite channel** section to the existing Selections panel, beside the distinct **From a layer** workflow. Its source is always the current final visible composite. No layer selector, threshold, transfer-function selector, editable channels, source-image selector, file upload or RGB channel painting is exposed.

Controls are **Channel** (Red, Green, Blue, Encoded luma, Alpha), **Combine** (Replace, Add, Subtract, Intersect), **Invert coverage**, an independent **Preview coverage** action and **Load selection**. Defaults are Encoded luma, Replace and inversion off. Every action has a label and keyboard focus state; use existing dark fields and stacked rows at the narrow inspector width. Channel controls are local drafts until Load. They do not dispatch on change or change the active selection merely by opening the section.

Always-visible guidance: “Build a selection from the visible composite. White selects fully; gray selects partially.” When inversion is enabled, show “Inversion also selects fully transparent pixels.” Subtract and Intersect require a non-null active selection; explain that requirement and disable only Load. An explicit empty selection remains valid. Add without a selection is allowed. Existing canvas-selection feather/inversion toolbar values are not silently injected into this command.

An accessible collapsed **How channel coverage works** disclosure explains that RGB components are multiplied by composite alpha; encoded luma is rounded to a byte before alpha multiplication; Alpha uses transparency directly; inversion happens after that calculation. The active selection does not restrict measurement and is combined afterward. Luma is encoded Rec.709 weighting, not linear-light luminance or perceptual lightness. Add takes maximum coverage; Subtract retains the existing selection in proportion to one minus loaded coverage; Intersect multiplies coverage. This is Prism's declared native policy, not Photoshop byte parity.

Loading makes one undoable selection change and keeps this panel open. Preserve channel/mode/invert for another deliberate operation; do not automatically load it again or switch tools. Existing Save selection, masked adjustments, mask capture and selection painting provide the next steps. Saving is explicit, uses the existing 16-slot library and does not mean creating an editable RGB channel.

## Exact commands and independent capabilities

Load sends only `{documentId, expectedRevision, channel, mode, invert}` to `load_channel_selection`; revision is positive and mandatory. Preview sends `{documentId, expectedRevision, channel, invert, maxEdge}` to `get_channel_preview`; the UI always supplies the captured positive revision even though the read API permits omission. Neither request includes layerId, source, feather, reduced preview pixels or a client-created asset descriptor.

Use a small pure support helper and types, with Native backend, connected status, exact `channelSelectionPolicy:'composite-byte-alpha-v1'`, exact `denseMaskPolicy:'framed-raw-alpha8-v1'`, a well-formed string array containing all five required `channelSelectionChannels`, and validated dense limits. Unknown future string entries may coexist with the complete known set; malformed/mixed/nonarray lists fail closed. A missing known channel does not authorize the partial producer under this complete-policy contract.

The native proposed dense limits are `{headerBytes:32,maxDimension:8192,maxPixels:24000000,maxWorkingBytes:268435456,maxPrepareWork:384000000,maxHistoryAssets:256,maxHistoryBytes:3221225472,yieldVisits:65536}`. Header size is the exact format invariant. Numeric quotas must be finite positive safe integers and internally consistent; valid lower resource ceilings are honored, not required to equal these shipped maxima. Do not reproduce the native graph/history/work formula in UI. The active canvas and any consumed alpha8 descriptor must fit advertised dimensions/pixel bounds. Native admission remains authoritative.

`channelPreviewLimits` is separate from mask inspection: `{maxEdge:2400,defaultMaxEdge:700,maxBytes:8388608,maxWorkingBytes:268435456,yieldVisits:65536}`. Validate fields, minimum supported edge 32, default edge within the declared range, positive safe byte/work/yield bounds and the protocol's hard upper edge. Honor lower valid limits. Preview requires its own command and these read limits; Load requires its own mutation command. Preview-only remains useful, and load-only does not need a successful preview. Explicitly malformed preview limits disable Preview without inventing a fallback; they do not disable an otherwise supported Load.

Preserve drafts and a clear explanation after same-document capability withdrawal. Do not reset Channel or Invert to get around a missing policy. Keep the section mounted once it is being used while its capability changes; document/backend navigation may reset this document-local draft. The Selections tab availability must include either independently supported channel command, not depend on `save_selection` or `load_layer_selection` being advertised.

## Read-only preview and request ownership

The channel preview is an inline disclosure in this section, not a new mask-inspection source. A deliberate Preview request expands an opaque grayscale image and a small toolbar for longest-edge size and Fit/100% preview-pixel display. Initial longest edge comes from the valid advertised default. Offer a small set of valid sizes, bounded by current limits. A previously chosen withdrawn size remains visible as unavailable until the user chooses another; never resend an over-limit request or silently reinterpret the draft.

Preview is **candidate channel coverage before combination**. This label remains visible when Combine is Add/Subtract/Intersect, so the image does not falsely promise the eventual combined selection. Changing Combine need not re-render the same coverage. Caption records source canvas dimensions, output dimensions, channel, inversion and inspected revision. “Nearest-sampled preview; small details may be omitted” appears for reduction. Load always re-renders full resolution at its captured revision; no preview image supplies editing pixels.

Use a bounded read request with AbortController, a monotonically increasing request/ownership sequence, and captured backend/document/revision/dimensions/channel/invert/edge/full relevant capability signature. Clear the old image immediately on any mismatch. Away-and-back options/capabilities cannot revive a response. Abort and ignore late success, errors and image-decode callbacks on replacement/unmount. Selected layer, inspector scrolling and Fit/100% display scale are not source changes. Changing a source option invalidates the old image and requires Preview again; it does not perform repeated full composite renders while the user navigates the controls.

Validate the response before display: exact document/revision/source dimensions/channel/invert/maxEdge, `coveragePolicy:'composite-byte-alpha-v1'`, `sampling:'nearest-pixel-center'`, opaque PNG contract, expected half-up output dimensions and bounded nonempty encoded data. The backend owns PNG pixel construction; the client does not duplicate its channel arithmetic. A malformed response shows a read error instead of an old/partial image. The image `onLoad`/`onError` handler is request-owned too.

Any document revision change invalidates a preview, including a new active selection: conservative revision pinning is intentional even when that particular edit did not alter RGB. Keep parameters, show “The document changed. Preview the current revision.” On a stale read, a deliberate refresh may read fresh metadata first through a guarded same-document handoff and then request that revision; never overwrite a newer visible graph or issue a mutation from an unseen local-only snapshot. Resource refusal leaves every draft intact. Preview failure does not create history or an asset.

## Load ownership and recovery

`load_channel_selection` is document scoped. Current `App.run` only exempts captured Resize from selected-layer coupling, and its ordinary guarded-result set does not cover the layer-selection loader. Reusing `captureGesture(document)` unchanged would therefore be wrong: when a layer is selected its missing targetLayerId fails preflight, and an unguarded result can reopen a navigated-away document.

Add a narrow channel-selection context to `GestureContext` and App.run, recognized only for this new command. Capture document/backend/revision/canvas dimensions, channel/mode/invert and an App-owned monotonic document/capability epoch. Validate before dispatch, before metadata installation, in `updateDocument`'s preview-acceptance callback and after its awaited preview. Validate returned document identity/backend, unchanged canvas dimensions and exactly one accepted own revision. The own-revision handoff must not invalidate itself merely because the active selection changes.

Do not couple a valid document operation to selectedLayerId, the availability of a saved-selection slot, a currently selected library entry or panel visibility. Selecting a different layer or closing the section while Load is pending must not discard a valid same-document result. Document/backend away-and-back or producer-policy loss does invalidate the old ownership epoch, even if equality later returns. UI-local status completion separately checks the initiating section/draft session so a finished request cannot clear newer controls or reopen a panel. No unconditional modal-close callback is needed.

Load disables mutable channel/mode/invert controls while pending; view scale and help remain inspectable. Use existing global busy dispatch guard too. A stale revision can refresh the current graph under the same captured ownership with pre/post-preview checks, retain the requested parameters and require another deliberate Load. Never automatically replay, change mode or weaken resource settings. For an ambiguous transport result, mark this local submission unconfirmed and offer **Review current selection** (guarded fresh metadata/coverage), preventing duplicate Load on the old unseen revision. This record is owned by the App document session and survives Selections-panel teardown; remounting cannot bypass Review. It is not a new receipt log, persisted recovery service or change to recipe retry infrastructure. A replacement draft/session is not cleared by an old error.

## Dense metadata, labels and honest canvas overlay

In `client/api.ts`, retain a legacy mask type and add a discriminated `Alpha8Mask` with `shape:'alpha8',asset,bytes,width,height,x:0,y:0,feather,invert`. `Mask` is their union; positioned additional masks contain this union. The source-filter-mask type explicitly unions alpha8 with its existing allowed geometric/bitmap shapes rather than using a widening `Omit` that accidentally permits unrelated fields. Client geometry-authoring inputs remain legacy geometric types. Add channel response/capability types; there is no public byte plane or local asset path.

`documentSelection` already returns native metadata intact. Preserve it through updates/Escape; do not manufacture runs or convert dense metadata merely to fit an old control. Introduce a small shape-label helper for actual identified display consumers:

| Existing seam | Required bounded change |
| --- | --- |
| `SavedSelections.describe` | Alpha8 is “Pixel mask”, with dimensions/feather/inversion. It currently falls through to “Rectangle”. Never infer empty coverage from absence of runs. Existing explicit empty RLE labeling stays exact. |
| `SelectionOptions` | Display “Pixel mask”, not an implementation token or a fabricated geometric boundary. Feather/invert continue to target native coverage. |
| `LayerMaskProperties` | Label dense/positioned-source coverage as a pixel mask; retain source frame, position, density and cutout distinction. Do not imply it was necessarily painted. |
| `FilterMaskControls` | Summary must identify a pixel effect mask instead of its current rectangle fallback. Editing/capture additionally requires alpha8 support in the existing shape list and dense policy when relevant. |
| `MaskInspection` | Dense selection/additional/filter reads require the dense marker/limits in the appropriate read identity, as well as existing source/mode/command gates. Enforce current maxEdge for these new dense paths; a missing capability cannot display a stale image. Retain source-size filter-mask inspection and positioned-mask canvas inspection. |
| `CanvasTools.SelectionOverlay` | Add an explicit alpha8 branch before SVG rectangle fallback. Never pass it to the current runs-only canvas renderer. |

For alpha8 canvas selection, request the existing bounded `get_mask_preview(source:'selection')` at the current revision. It evaluates the actual saved selection including feather/inversion and reads only its selected alpha asset. Decode its opaque grayscale preview locally and tint coverage with the established translucent purple, using the response's bounded dimensions and pointer-events:none. The image-decode/tint stage remains tied to the same request key. Use a longest-edge bound on both axes, not the old bitmap renderer's width-only scaling. No raw hash endpoint, RGB composite request, client feather evaluation, RLE expansion, density reconstruction or exact contour claim.

The overlay request identity includes document/backend/revision/selection descriptor and read capabilities/limits. Hide/clear it immediately while a local geometric selection or crop draft replaces the active selection, on deselect, capability loss or revision change; late decode cannot tint a newer draft or another document. Loading/error/unsupported states display an unobtrusive “Pixel selection active; coverage overlay unavailable” hint with Inspect coverage when supported. The mask still exists and editing retains native semantics. Do not replace unavailable coverage with a full-canvas rectangle or treat it as no selection. Keep legacy geometry/RLE overlay behavior unchanged in this slice; improving their pre-existing display approximations is separate work.

Channel preview intentionally renders RGB; existing mask inspection and the saved-selection overlay do not. Main UI copy needs only the user distinction (“composite channel” versus “active selection”); technical read-path claims belong in documentation/tests, not repeated warning text.

## Existing consumers and capability boundaries

The new producer may appear only after native support is complete across the consumers in the architecture map. No UI option exposes RLE versus alpha8 or threshold/reduce fallback. Sparse results may remain existing RLE; a later edit may change representation without changing coverage. Both labels remain “Pixel mask”.

When a current or saved dense descriptor is present but its storage semantics/limits are unavailable, allow inert metadata inspection and independently available removal/deselection. Block actions that must consume/copy that descriptor instead of silently dropping it: saved selection load/save/update; refine/paint/morph; layer-mask copy/position/rasterization; effect-mask capture/edit; selection-scoped adjustment/Lookup creation and paint/fill. Include dense capability changes in touched mask/selection submission identities. Filter effect-mask support remains independent of whole-layer transparency and requires its existing source policy/capture-geometry contract; a Distort or unsupported resample still rejects capture.

Do not create a blanket “any alpha8 in history blocks all editing” rule. Gates follow the actual active selection/target mask dependency; metadata-only rename/delete and unrelated legacy controls retain their existing gates. Native graph validation, rendering, resource and protection rules remain final. Inactive/disabled/zero-density dense references still belong to native persistence/transfer accounting; the UI does not remove them to make a command fit.

Recipes retain existing behavior: masks are not serialized into ordinary recipes, masked filter-stack capture still refuses unless Filters is explicitly unchecked, and a dependency-free recipe can operate on a supported document/target containing dense masks. No fake hash-only mask portability is introduced. Existing complete definitions, retry behavior and LUT dependency rules stay unchanged. PSD can still reject effective fractional mask coverage that cannot be represented exactly; a new storage format does not promise broader PSD semantics.
