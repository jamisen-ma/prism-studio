# Prism integration contract — version 1

Product: Prism Studio. Root owns server service, validation, MCP, package/scripts/docs. Native agent owns `server/native.mjs` and native tests. Photoshop agent owns `photoshop-plugin/**`. Frontend agent owns `client/**`, `index.html`, `vite.config.ts`, `tsconfig.json`, `public/**` (coordinate fixtures). Do not change another owner's files without coordinating.

## Backend interface

`export class NativeBackend { constructor({dataDir}); async init(); async execute(command, args = {}); }`

`execute` returns a serializable result. A command error is `Error` with `.code` string. Backend capability object lists supported command names. Document mutations take `documentId`, normally optional `expectedRevision`, and return `{document, ...}`. Recipe application, filter baking, filter-mask edits and four-corner Distort require a positive revision explicitly; document creation/import allocate a new document instead. Document has `{id,name,width,height,revision,backend,layers,history,canUndo,canRedo}`. Layer has `{id,name,type,visible,opacity,blendMode, ...}`. History is `[{id,label,timestamp}]`. ID strings everywhere; units pixels; opacity 0..1. Native documents use immutable source assets and persisted project graphs, not full-image regeneration. Service serializes commands per backend and handles idempotency for mutation requests. Backend rejects revision mismatch itself as a second guard.

MCP command and custom-tool inputs use strict object schemas. Unknown options reject before dispatch rather than being stripped into a different valid request. Generation tools also reject a supplied `mode`: choose `prism_generate_image` or `prism_edit_image` explicitly. Supported defaults, retry identifiers and companion cross-field validation remain unchanged.

Common commands and args:
- `capabilities` -> `{backend,commands:[string],limitations:[string]}`
- `list_documents` -> `{documents:[document]}`
- `get_document` `{documentId}` -> `{document}`
- `create_document` `{name,width,height,background:'#RRGGBB'}` -> `{document}`
- `import_image` `{name,data:base64,mimeType}` -> `{document}` (native required; Photoshop may unsupported initially)
- `get_preview` `{documentId,maxWidth?:number}` -> `{data:base64,mimeType:'image/png'|'image/jpeg',width,height,revision}`
- `add_adjustment` `{documentId,expectedRevision?,kind,value,parameters?,name?,mask?}` -> `{document}`. Choose from advertised `adjustmentKinds`; the current native engine has 27 kinds. Scalar bounds and typed parameter shapes are authoritative in [shared validation](../shared/commands.mjs); Levels, Curves, Channel Mixer, Gradient Map, Color Balance, Black & White, Selective Color and targeted Hue / Saturation use parameters and value 0. Public explicit masks are rectangle/ellipse/polygon descriptors with feather/inversion. The optional bridge rejects unsupported kinds/options. See [color mapping](COLOR_MAPPING.md), [tonal color](TONAL_COLOR.md) and [professional controls](PRO_TOOLS.md).
- `set_layer` `{documentId,expectedRevision?,layerId,name?,visible?,opacity?,blendMode?}` -> `{document}`
- `duplicate_layer` `{documentId,expectedRevision?,layerId}` -> `{document}`
- `delete_layer` `{documentId,expectedRevision?,layerId}` -> `{document}`
- `reorder_layer` `{documentId,expectedRevision?,layerId,index}` -> `{document}`
- `add_text` `{documentId,expectedRevision?,text,x,y,fontSize,color,name?}` -> `{document}`
- `crop_document` `{documentId,expectedRevision?,x,y,width,height}` -> `{document}`
- `resize_document` `{documentId,expectedRevision?,width,height,resample?:'nearest'|'cubic'|'mitchell'|'lanczos3'}` -> `{document}`. Native `documentResizeMethods`/`documentResizeDefault` advertise supported methods. Omitted or explicit Lanczos3 retains the legacy transform and pixels. Nearest copies pixel-center sampled RGBA; photographic methods retain their reduction kernel with cubic enlargement. Masks, selections, guides, protected proportions and positioned-mask review keep existing rules. Explicit methods reject on the optional bridge. See [resampling](RESAMPLING.md).
- `select_subject` `{documentId,expectedRevision?,layerId?}` -> `{document}` Native uses the installed local alpha model; optional `layerId` scopes the source. Photoshop uses host subject selection without layerId.
- `select_rectangle` `{documentId,expectedRevision?,x,y,width,height}` -> `{document}`
- `clear_selection` `{documentId,expectedRevision?}` -> `{document}`
- `apply_transaction` `{documentId,expectedRevision?,label,operations:[{command,args}]}` -> `{document}` atomic group of document edits, one undo step, rollback on error. Member commands cannot create/import whole documents, export/save/undo/redo/nest transactions or change documentId. Bounded Color Lookup asset imports are explicitly permitted. Root validates members as well.
- `undo` / `redo` `{documentId,expectedRevision?}` -> `{document}`
- `save_document` `{documentId}` -> `{document,saved:true}` native always persist; Photoshop save only existing path, otherwise user dialog or explicit unsupported
- `export_document` `{documentId,format:'png'|'jpeg'|'webp'|'tiff',quality?:1..100,matte?:'#RRGGBB',density?:1..1200,lossless?:boolean}` -> `{data:base64,mimeType,width,height,filename,flattened:true,bitDepth:8,colorSpace:'sRGB',density?}` for native exports (no arbitrary filesystem writes). Matte is JPEG-only, lossless is WebP-only, density is PNG/JPEG/TIFF-only and changes metadata rather than pixel dimensions. TIFF uses lossless Deflate compression and retains alpha. These options are advertised through `exportFormats`, `exportOptions` and `exportDensityFormats`; the optional Photoshop bridge supports only PNG/JPEG and quality. MCP writes a new unique file beneath the configured exports directory and returns its path instead of base64 data.

Not every backend supports every command. Expose accurate capabilities; unsupported errors are explicit. Photoshop document fields may include limitations (do not invent history).

Adjustment scoping: an explicit mask overrides the current selection; otherwise an existing document selection scopes the adjustment. With neither, apply to the whole canvas. UI must synchronize selection from backend document state after undo/redo and external edits. Native layers are bottom-to-top; Photoshop layers are top-to-bottom and include nested children. Respect the returned `layerOrder`.

## Native Layer Fill

`set_layer_fill` accepts `{documentId,expectedRevision,layerId,fillOpacity}` and returns `{document}`. The revision is required and positive; Fill is a required finite Number from 0 through 1, with no coercion or extra fields. Transactions require the positive revision on the enclosing command. Native discovery advertises `layerFillPolicy:'content-alpha-outside-effects-v1'` and `layerFillContentTypes:['raster','solid','text','shape','path','gradient']`; the optional bridge refuses this command. Public layers expose nonunit `fillOpacity` separately from ordinary numeric overall `opacity` and flat outside `effects`.

Body composition uses overall opacity times Fill without intermediate alpha-byte rounding; outside styles use overall opacity and the original unfilled silhouette. Fill 1 retains legacy arithmetic and records. Protected values cannot change without explicit unprotection; identical values remain accepted under ordinary revision/history semantics. Positive Fill retains conservative source-alpha protection; Fill 0 protects only outside decoration. Clipping participants require Fill 1. Groups and adjustments are ineligible.

Nonunit Fill is stored privately in a strict versioned effects wrapper, which old readers reject. Public projected `fillOpacity` must never be written back as internal graph metadata. Current/history/bundle validation checks the wrapper before asset reads. Styles and ordinary recipes retain the target Fill without capturing it; raw source inspection/selections, extraction and unfilled placement remain distinct from display consumers. PSD export reports `FILL_UNSUPPORTED`, while flattened exports render Fill and editable native projects retain it. See [the user workflow and exact boundaries](LAYER_FILL.md).

## Imported Color Lookup

Native `import_color_lookup {documentId,expectedRevision,target:'adjustment'|'layer-filter',layerId?,filterId?,data,sourceName,inputSpace:'srgb'}` atomically imports or replaces a lookup and returns `{document,layerId,filterId?}`. A positive revision is required, including on the enclosing transaction. Creation omits the applicable target ID; replacement retains saved settings, masks and order. Source creation requires `layerId`; global replacement requires the existing lookup adjustment ID. The complete descriptor is `{asset,bytes,gridSize,inputSpace,sourceName,title?}` with a verified immutable original asset. Add commands require the complete descriptor with value0; empty parameter updates retain it, and nonempty updates replace it completely.

Require native `colorLookupPolicy:'cube3d-f64-trilinear-srgb-v1'`, `cube-3d` format, `srgb` interpretation, valid advertised limits and the scope's kind/command. Strict UTF-8 3D `.cube` files admit2–33 grids, at most4MiB of original bytes, exact authored0–1 samples/domains and original Float64 samples. Source work32 per pixel composes with existing blend/mask costs. Active preparation sums to32MiB per nominal graph pass; history retains at most128 unique LUTs/64MiB original bytes. Original files travel in `.prism`; recipes with LUT dependencies are explicitly refused. Ordinary recipes retain unrelated existing lookups. MCP `prism_import_color_lookup_file` reads one bounded absolute regular `.cube` path with a required stable request ID. See [workflow and complete contract](COLOR_LOOKUP.md) and [transport details](COLOR_LOOKUP_MCP_DESIGN.md).

## Native Photo Filter

The global/source `photo_filter` kind requires `value:0` and optional flat parameters `{color,density,preserveLuminosity}`. Color is exactly a six-digit RGB hex triplet; uppercase canonicalizes to lowercase. Density is finite0–100 in exact0.01% increments, and preservation is strictly Boolean. Defaults are `#ff9500`,25 and true. Sparse updates retain omitted fields; canonical recipes reset all three effective values.

Require Native, `photoFilterPolicy:'rgb-transmission-luma-fit-v1'`, the scope's kind/command and source coordinates for filters. The native encoded-RGB transmission formula restores unrounded weighted luma when requested and fits out-of-gamut colors through shared chroma reduction before exact half-up bytes. Alpha and hidden RGB remain unchanged. Source work16 per computing pixel or1 for a proved identity composes with the existing blend/mask costs; no new asset or full-plane cache is used. Identities retain entry blending and protection/edit guards. See [controls, endpoints and MCP example](PHOTO_FILTER.md).

## Curves interpolation

Global/source Curves also supports `parameters:{mode:'banks',banks:{master?,red?,green?,blue?}}`, with each bank containing optional points/interpolation on input and complete explicit settings in canonical records. Require `curvesBanksPolicy:'master-byte-then-channel-byte-v1'`, all four advertised `curvesBankNames`, and the existing context kind/command. Any Smooth bank additionally requires the Smooth capability, including hidden or identity banks. Master byte lookup precedes component byte lookup; entry blending and opacity apply once to the completed candidate.

Same-mode bank patches retain omitted banks and fields. Switching representations is explicit: `mode:'banks'` on a single curve starts from submitted/default bank settings; `mode:'single'` on banks replaces the entire bank set with submitted/default legacy settings. Old-style fields without an explicit transition cannot collapse banks. Single-curve canonical records and legacy recipe hashes stay unchanged; recipe staging supplies the required transient single/Linear reset. See [full bank contract and examples](CURVES_BANKS.md).

Existing global/source `curves` keeps value0 and gains optional `parameters.interpolation:'linear'|'smooth'`. Points and channel are also optional on add/update; effective points still require2–16 finite values in0..255, strict X order and X endpoints0/255. Supplied points replace the complete list. New curves default Linear; partial updates retain omitted mode. Explicit Linear removes the canonical stored mode, while Smooth stays explicit for old-reader rejection.

Require Native plus `curvesInterpolationPolicy:'shape-preserving-pchip-v1'`, a modes list containing Smooth, and the context’s advertised kind/command. The new helper compiles a256-byte native lookup; no new image plane, command, filter kind or source-work weight is introduced. Global and source callers retain their distinct existing hidden-RGB policies. Full canonical adjustment recipes explicitly reset a Smooth target when their saved mode is Linear. See [the complete contract](SMOOTH_CURVES.md).

## Editable four-corner Distort

Native `add_layer_distort {documentId,expectedRevision,layerId,corners}`, `update_layer_distort {...,transformIndex,corners}` and `delete_layer_distort {...,transformIndex}` return `{document}`. All require a positive revision, or a positive outer revision in an atomic transaction. Corners are a complete strict `[topLeft,topRight,bottomRight,bottomLeft]` array of `{x,y}` in stage pixel-edge coordinates. The index addresses the full geometry list. Output dimensions stay equal to that stage’s input dimensions, permitting historical edits without resizing the suffix.

Require `layerDistortPolicy:fixed-frame-projective-bilinear-v1`, `layerDistortCoordinates:stage-pixel-edges`, an eligible advertised content type and the corresponding command. Raster, solid, text, shape, path and gradient are eligible; protected targets reject. Bounds, numerical admission, fixed mask spaces and resource preflight are specified in [the Distort contract](DISTORT.md). No recipe steps or generated pixels are involved.


## Native Selective Color

The global/source `selective_color` kind requires `value:0`. Parameters are optional `method:'relative'|'absolute'` and nine optional `[Cyan,Magenta,Yellow,Black]` rows named reds/yellows/greens/cyans/blues/magentas/whites/neutrals/blacks, each −100..100 in exact0.01% increments. Defaults are Relative and all zeros; supplied rows replace complete tuples while omitted rows/method retain current values on update. Recipes normalize to all effective settings, so defaults reset an existing target.

Require Native, `selectiveColorPolicy:'rgb-partition-cmyk-v1'`, complete recognized methods/ranges and the individual context kind/command; source authoring also requires source coordinates. Original encoded-RGB memberships are evaluated simultaneously, additive virtual CMY+K corrections are summed, and channels clamp/round once. Alpha and hidden RGB remain exact. Computing source work is12 per pixel, authored-all-zero1, inactive0, plus existing blend/mask weights; no new full-plane cache. Relative cannot change pure white. This is native RGB8 correction, not print CMYK or Adobe parity. See [Selective Color contract and examples](SELECTIVE_COLOR.md).

## Native targeted Hue / Saturation

The global/source `hue_saturation` kind requires value0 and optional Master plus six named color-range triples `[Hue,Saturation,Lightness]`. Hue is −180..180; Saturation/Lightness are −100..100, with exact0.01 increments and zero defaults. Supplied complete triples replace rows, omitted rows retain, and canonical recipes reset all seven. Require Native, `hueSaturationPolicy: 'rgb-hue-triangle-hsl-v1'`, all seven recognized `hueSaturationRanges`, the context kind and command, and source coordinates for filters.

Original input hue weights target Hue/Saturation; named Lightness is attenuated by original chroma. Saturation scales proportionally, and exact gray cannot be colorized by Hue/Saturation. The fixed native binary64 conversion has explicitly documented half ties. Alpha and hidden RGB remain exact. Computing source work32, authored-all-zero1 and inactive0 combine with existing blend/mask weights. No extra image plane or asset is added. See [contract, numerical limits and MCP example](TARGETED_HSL.md).

## Native layer groups

The native `layers` array is a bottom-to-top, depth-first tree: each group header precedes its contiguous descendant block. A layer's optional `parentId` references its containing group; absent/null is root. Group nodes have `type:'group'`, `mode:'pass-through'|'isolated'`, visibility, opacity and an optional mask/density. Pass-through requires `blendMode:'normal'`; isolated groups support the27 native blends. They have no pixel dimensions or transforms. There are at most eight nested groups and64 total nodes, including group headers. See [group compositing](GROUP_COMPOSITING.md) for the current declared semantics.

- `create_group` accepts the usual document revision fields plus optional `name`, `parentId` and direct-sibling `index`; creates an empty group.
- `group_layers` accepts unique `layerIds` that are contiguous direct siblings under one parent, plus optional `name`; preserves subtree order.
- `move_layer` accepts `layerId`, `parentId` (null for root) and optional sibling `index`; moves a whole subtree and rejects cycles.
- `ungroup_layer` accepts a group `layerId`. A nonempty group must be pass-through, visible with opacity1 and no mask to preserve the image exactly. Empty groups can be ungrouped.
- `set_group_compositing` accepts a group `layerId`, `mode` and optional isolated `blendMode`; protection and isolation-context changes are checked before mutation.

These commands are native-only, transactional and undoable. Duplicate/delete operate on whole subtrees; duplication remaps IDs, parents and clipping links. `reorder_layer.index` is a direct-sibling index, retaining the previous behavior for flat documents. Pass-through group opacity/masks interpolate the completed before/after composite once in premultiplied RGBA. Isolated groups render internal content on transparency, then apply blend, opacity and mask once to that result. Source assets remain immutable. Group masks also clip decorations. Neutral pass-through groups avoid retained full-image buffers; isolated and nonneutral groups share the256 MiB retained-buffer preflight with filters and clipping chains.

Protected descendants block group deletion, opacity and isolation-mode/context changes, including when hidden or masked. Protected content cannot be moved under a faded ancestor. Groups do not support transforms, outside styles, rasterization or proportional placement; content layers have their separate commands. Placing a leaf from nested neutral groups is supported, but `place_layer` rejects any isolated, masked or translucent ancestor because flattening those settings would change appearance or editable effects. Arrangement also rejects isolated ancestors. Group/leaf previews respect ancestor compositing, masks and opacity while showing the requested content for inspection. Complete clipping chains can move structurally together; partial-chain changes require release. See [clipping chains](CLIPPING.md).

## Reusable native recipes

Native documents expose a document-local `editRecipes` library. Six standalone commands save/get/rename/delete/validate/apply typed definitions; they cannot be nested inside `apply_transaction`. Recipes bind named slots to distinct explicit current-layer IDs and support filter addition, existing-adjustment updates, text styling and outside effects/outlines. Validation stages the same mutations and complete prospective history envelope without image I/O. Application requires `expectedRevision`, commits once and uses the service's session-only request deduplication. Never rebase an uncertain application automatically. See [recipe limits, semantics and MCP](EDIT_RECIPES.md).

## Explicit source filter baking

Source-filter discovery now includes 31 kinds. `layerFilterSpatialPolicy:'alpha-weighted-gaussian-rgb-v1'` identifies source `blur` and `sharpen`: authored Gaussian sigma0–50/0–10, preserved alpha and hidden RGB, fixed-amount-one RGB unsharp and explicit source-radius work/cache admission. Existing global blur/LAB-sharpen behavior stays unchanged. See [source spatial filters](SOURCE_SPATIAL_FILTERS.md).

The distinct source-only `unsharp_mask` uses `value:0`, complete default parameters `{amount:100,sigma:1,threshold:0}`, and `layerFilterUnsharpPolicy:'rgb-residual-threshold-v1'`. Amount0–500 uses exact0.01% increments, sigma0–50 has no positive floor, and threshold is an integer0–255. Updates merge supplied fields. Threshold compares each unrounded RGB residual strictly; amount scales that residual before one clamp/round, then opacity blends the candidate. This independent marker plus source coordinates and the individual kind defines support; global adjustment kinds/parameters remain unchanged. Nonidentity work is source pixels × `(2K+40)`, and amount0/sigma0/threshold255 costs one visit per pixel without a ring while retaining structural active guards. See [Unsharp Mask contract](UNSHARP_MASK.md).

The source-only `add_noise` uses `value:0`, defaults `{amount:5,distribution:'uniform',monochromatic:true,seed:1}` and the independent `layerFilterNoisePolicy:'seeded-rgb-discrete-v1'`. Amount is 0–400 in exact 0.01% increments; the saved seed is an integer from 0 through 4294967295. Updates merge effective fields. Deterministic source-coordinate samples use exact additive byte rounding before filter opacity; alpha and hidden RGB stay exact. Computing entries cost eight weighted source visits, Amount0 costs one, and computing Gaussian reserves one shared 4096-byte table across graph peaks and every Bake phase. Global adjustment commands reject this family. See [Add Noise contract](ADD_NOISE.md).

The source-only `high_pass` uses scalar sigma `value:0..50` and no parameters under `layerFilterHighPassPolicy:'alpha-weighted-residual-128-v1'`. It rounds `128 + input RGB − exact alpha-weighted Gaussian mean` once, preserving alpha and hidden RGB. Sigma zero computes gray 128 with work one per pixel and no ring; positive sigma has the source Gaussian `(2K+8)` work/cache policy. Optional blending and opacity follow the byte candidate. Gray 128 is byte-neutral for Overlay and Soft Light after rounding, but not universally neutral. Structural guards remain active at zero sigma. See [High Pass contract](HIGH_PASS.md).

The source-only `shadows_highlights` uses `value:0`, defaults `{shadows:25,highlights:0,shadowWidth:50,highlightWidth:50,sigma:3}` and independent `layerFilterLocalTonePolicy:'alpha-weighted-local-tone-v1'`. Amounts accept 0–100 and widths 1–100 in exact 0.01% increments; source sigma accepts any finite 0–50 value. Partial updates merge effective defaults. The alpha-weighted neighborhood drives an endpoint-preserving rational RGB curve before entry blending, opacity and the completed stack's effect mask. Both zero Amounts produce an identity candidate but retain active-stack guards and optional blending. Computing work is 16 source visits per pixel at zero sigma or `2K+20` at positive sigma; the two-channel row cache and 2 KiB response table participate in existing graph and Bake preflight. Global adjustment commands reject this source-only kind. See [Local Shadows / Highlights](LOCAL_SHADOWS_HIGHLIGHTS.md).

Source entries also accept optional `blendMode` under `layerFilterBlendPolicy:'candidate-rgb-v1'` and the separately advertised 26 `layerFilterBlendModes`. Normal is omitted on canonical authoring; missing updates preserve the current mode, explicit Normal resets it. The full-strength byte candidate blends against its input before filter opacity, without an extra alpha factor. Candidate identities can still change RGB under non-Normal modes. Each active non-Normal entry adds 40 weighted source visits per pixel to the preceding candidate costs. Global adjustments remain unchanged. See [filter-blend precision, capabilities and persistence](FILTER_BLENDING.md).

`bake_layer_filters {documentId,expectedRevision,layerId}` retains the archived original, source alpha, separate cutout alpha, source dimensions, additional layer masks and geometry while materializing the current source-filter RGB into a new working image and clearing the stack plus any filter effect mask. Its capability is `layerFilterBaking:'source-rgb'`. A nonempty inactive stack clears without image I/O. Protected targets reject; active stacks also reject any earlier protected content node, including hidden nodes. See [exact pixel, context and resource semantics](FILTER_BAKING.md).

Standalone baking and bake-containing transactions require a positive enclosing revision; individual transaction steps carry no revision. Native entry captures those arguments before queuing. The existing new-asset ownership scope covers the complete bake-containing transaction through commit, including later brush writes, and removes only owned new files on prepublication failure. Existing deduplicated blobs stay intact. Every source/output comparison admits bounded regular files on one nonblocking, no-follow descriptor before allocating a read buffer. Temporary PNG output is admitted before reading and cleaned up after success or handled failure. These operations do not enter metadata-only recipes.

## Source filter effect masks

`set_layer_filter_mask`, `modify_layer_filter_mask` and `clear_layer_filter_mask` require a positive captured revision and a nonempty raster filter stack. They are native-only and transactional; the enclosing transaction supplies its positive revision. Discovery separately advertises `layerFilterMaskPolicy:'source-stack-alpha8-v1'`, source coordinates, supported sources/shapes/properties and `layerFilterMaskCaptureGeometry:'integer-copy-v1'`. Protected targets reject every edit.

One source-space mask mixes the completed stack with its pre-stack working RGB once, before geometry. Rectangle, ellipse and source-sized alpha8 bitmap descriptors are strict. Set accepts all, none, explicit mask or a snapshot of the current selection. Selection capture requires every retained geometry step to be an exact integer copy and preserves intermediate clipping; resampling, rotation, flips and fractional mapping refuse. Disabled masks or density zero reveal the whole filtered result without discarding saved coverage. Density uses the defined native alpha8 floating stage; final RGB mixing is exact integer half-up. Alpha and hidden RGB remain unchanged.

Public documents retain a filter-entry array plus read-only `filterMask`; persisted masked stacks use a versioned wrapper rejected by older readers. Entry edits retain it; final-entry deletion, Clear and Bake remove it. Mask-only removal preserves entries. Recipes cannot capture mask coverage, while appending supported filter recipes retains the target's mask. Read-only `get_mask_preview` accepts `source:'filter-mask'`, returns source-frame dimensions and supports raw/effective modes without reading image RGB. Masks add bounded source work and phase-specific buffers; capture has separate admission and yielding. See [complete commands, precision and lifecycle](FILTER_EFFECT_MASKS.md).

## Additional mask positioning

Native `set_layer_mask_position {documentId,expectedRevision?,layerId,x,y}` sets absolute integer offsets. `apply_layer_mask_position {documentId,expectedRevision?,layerId}` means **Rasterize mask position**, not applying a mask to image pixels. Both support transactions. The retained source frame belongs only to additional masks; selections and public replacement-mask arguments reject it. Crop shifts retained coordinates exactly. Canvas bounds clip support according to zero-padding rules; painting/morphology explicitly materialize raw canvas alpha8 and preserve density. Image resampling requires explicit rasterization first. Source images and subject alpha remain unchanged. See [mask positioning](MASK_POSITION.md).

Transactions validate intermediate positioned graphs before later pixel operations. Retained source callback buffers join the existing group/filter/clipping resource preflight. Read-only mask inspection, selection loading and PSD export use the same raw/effective positioned coverage and retained-source dimensions; each preserves its separate operation budget and format limits.

## Detailed masks and composite channels

Native `load_channel_selection` requires a positive current revision and accepts `channel:red|green|blue|luma|alpha` (default luma), `mode:replace|add|subtract|intersect` (default replace) and Boolean `invert` (default false). It measures the final visible composite at full resolution, without restricting measurement to the selected layer or active selection. The latter participates only in combination. `get_channel_preview` independently reads an opaque grayscale PNG with an optional positive revision and `maxEdge:32..2400`, default700, using nearest pixel-center samples without enlargement. It changes no selection, asset or history entry.

The `composite-byte-alpha-v1` policy multiplies component bytes by alpha and rounds half up; luma first rounds `(2126R+7152G+722B)/10000` to a byte, then multiplies by alpha and rounds again. Alpha uses transparency directly. Inversion complements the finished coverage, including transparent pixels. Existing continuous active coverage combines before final byte rounding. Subtract/Intersect require an active selection; all-zero coverage remains an explicit empty mask. One load is one Undo step, including in an atomic transaction with a positive outer revision. No segmentation or generation runs.

The `framed-raw-alpha8-v1` representation supplements the unchanged200,000-run bitmap limit. Producers count exact nonzero constant runs, retaining canonical RLE when it fits and otherwise storing exact bytes in a32-byte-header immutable asset. Its strict descriptor contains shape, SHA256 asset, exact framed bytes, width/height, canonical zero x/y, feather and inversion. Ordinary geometric replacement APIs stay geometric. Explicit filter-mask reuse requires matching source dimensions and verified compatible ownership. Metadata is validated before snapshots or I/O; rendering receives private asynchronously prepared coverage, never an unprepared rectangle fallback.

All current mask consumers support the representation: selection algebra, saved masks, layer and source-filter coverage, paint/fill, morphology, bounds changes, generation snapshots/protection, inspection, PSD export, Undo, restart and portable state. Immutable source assets remain unchanged. The joint256MiB named-buffer and384-million-preparation-visit gates apply before relevant pixel work, including first channel loads on older graphs. They are not total process-memory bounds. History admits at most256 unique raw frames and3GiB after normal redo truncation/100-state retention; portable-project limits remain unchanged. Newly owned assets roll back on later command, transaction or persistence failure; old/shared files remain intact. See [user workflow and limits](DENSE_MASKS.md) and [precise resource design](DENSE_MASK_DESIGN.md).

## HTTP service on 127.0.0.1:43120

Native documents also expose `savedSelections:[{id,name,mask}]`, defaulting to an empty array for older projects. `save_selection` stores an independent active-mask copy; optional `selectionId` overwrites an existing entry and optional `name` sets its name. `load_selection` takes `selectionId` and `mode:replace|add|subtract|intersect` (default replace). Replace retains editable geometry; combinations produce bounded bitmap alpha. Add with no active mask restores the saved one, while subtract/intersect require an active selection. `rename_selection` and `delete_selection` leave the active selection unchanged. All four commands are native-only, transactional and undoable. Up to 16 entries are supported; overwrite remains available at capacity. Saved masks transform with crop, resize and canvas bounds, and count toward project metadata limits.

- `GET /api/session` -> `{token}` to same-origin/local frontend, used as Bearer for API. No remote CORS. Host/Origin validated.
- `GET /api/status` -> `{name:'Prism Studio',version,backends:[{id,label,connected,commands,limitations}],bridge:{connected,appVersion?,pluginVersion?},activity:[...]}`
- `POST /api/command` body `{backend:'native'|'photoshop',command,args:{},requestId?:string}` -> `{ok:true,result}` or HTTP 4xx/5xx `{ok:false,error:{code,message}}`
- `GET /api/activity` -> `{activity:[{id,backend,command,status:'success'|'error'|'running',label,timestamp,durationMs?,error?}]}`
- `GET /api/setup` -> `{bridgeUrl,pluginPath,mcpCommand,mcpArgs,token}` (authenticated; for pairing UI only).

Auth: all except session require Bearer token. Session bootstrap restricted to expected loopback Host and absent/trusted local Origin and Sec-Fetch-Site not cross-site. Frontend calls `GET /api/session` once then attaches token. In dev Vite port43110 proxies `/api` to43120. Production companion serves built `dist/`.

## Photoshop WebSocket protocol

Plugin connects `ws://127.0.0.1:43120/bridge`. Within 5s sends `{type:'hello',token,pluginVersion:'0.1.0',appVersion,capabilities:[command names]}`. Service replies `{type:'welcome',protocolVersion:1}`. It rejects second active connection rather than stealing current one. Server calls `{type:'command',id,command,args}`; plugin replies `{type:'result',id,result}` OR `{type:'result',id,error:{code,message}}`. Plugin serializes commands and wraps mutations in executeAsModal; use suspended history to group each command and rollback failure. Preview payloads are PNG/JPEG base64, not data URLs. No arbitrary script execution. Plugin can send `{type:'event',event:'document_changed'}`; service logs events. Ping/pong built-in socket heartbeat managed server-side. Commands have bounded timeout with explicit uncertain-result message on timed-out mutation; do not automatically retry mutations.
